## Design Decisions

- **DD-1 score_reference の導出元差し替え**: 探索で `CompositionScore` に旋律
  フィールドが存在しないことを確認 → 記号旋律の正典 = identity sidecar の
  `note_events_json`（note-events/0.1）を導出元に変更。設計書の趣旨（記号から
  決定論導出＝原曲側の抽出誤差ゼロ）は保存。bpm は arrangement 解決後の
  `derived_score` 由来とした（検収対象＝生成器へ実際に指示した内容のため）。
- **DD-2 型設計**: `ObservationAdherenceStatus`（2 値）と `arrange/observe.py` は
  一切変更せず、experimental 節に 4 値 D-1 Literal を直接持たせて既存スキーマ
  diff ゼロを達成。`recast/report.py` の写像が既に 4 語彙対応だった構造を利用。
- **DD-3 opt-in**: `axis_policy` の有無で分岐。宣言の無い melody anchor は現行
  挙動（LCS・本会計）を完全維持＝既存レポートの意味変更ゼロ。
- **DD-4 G2 帯域**: 帯域は機械検出不能なので backend 単位の**宣言** +
  fail-closed 既定（未宣言 → `band_out_of_validation`）とした。→ 後述の限界あり。
- **DD-6 G1 と fail-closed の二層**: registry 全体が未校正 → `not_observed`
  （エラーにしない・休眠）/ 部分校正済みで未校正軸を指定 → `RecastError`
  （設定の誤りは大声で失敗）。
- **会計分離**: experimental を本会計に混ぜない理由を「マージ日を境に既存
  レポートの数字の意味が変わるから」と明文化し、空なら serialize に現れない
  実装でバイト不変を担保。
- **R2-5 free 軸**: evidence 欠落は判定をブロックしない（load 時の全軸検証とは
  別レイヤ）。**R4-4 lenient-missing digest**: 欠落参照は決定論センチネルを fold
  して raise しない（未使用参照の欠落で通常観測を落とさず staleness 検出は保持）。
- **ラチェット終端化**: readback validator は R5-2 → R9-1 → R10-3 の 3 巡目で
  **境界宣言**（保証は (a) shape / (b) status↔evidence 整合 / (c) 確定 status の
  軸値存在 の 3 点のみ。M3 閾値からの verdict 再導出はしない＝報告層に M3 の
  意味論を二重実装しない）。plan 診断も R10-2 の runtime ゲート順一致で打ち止め。
  User から「オーバーエンジニアリングに気をつけて」の指示を受け、Round 11 以降の
  判定基準を「**正常な運用でユーザーが実際に踏むか**」に厳格化した。

## Handoff

### M4 の実効状態（最重要）

**M4 は現時点で完全に不活性**。G1（M3 registry が `uncalibrated`）が全経路を
止めるため、実世界で点灯するケースはゼロ。増えたのは「軸別契約を宣言できること」
「生成前に検収不能を診断できること」「結果を載せる場所と会計分離」であって、
**測れるようになったものは無い**。

### クリティカルパス

1. **M3d slow-lane 校正実測ひとつだけ**。ゲート機構・診断・読み戻し検証にこれ
   以上の層を足すのは、成果ゼロの上に厚みを足す行為（Codex 後半で境界宣言を
   入れたのはこの理由）。
2. 本番経路（Suno フルミックス → demucs stem）は **M2e / V-fullstack** まで別途
   点灯しない。M4 が狙う用途は二段階先。

### 新発見 — G2 の解像度不足（M3d と同時に是正すべき）

実装の G2 は backend 宣言 `melody_take_band == "clear_lead"` を見るが、M2 の実測は
**同じ clear_lead 帯の中で割れている**: S-direct（合成単旋律）= **fail**（VFA
0.259 単独超過）/ V-direct（実声 vocadito）= **pass**（RPA 0.9886）。したがって
M3d 校正後、合成素材が `clear_lead` を名乗って通過し、実声で校正した閾値が合成音
の分布に適用されうる。**Codex R1-1（route を crepe_direct へ束縛）と同型の問題**
であり、同じ処方（帯域語彙を M2 の実測区分まで細分するか、素材種を束縛する）で
是正する。なお M4d E2E は抽出器注入で配管を検証しており、実抽出精度には依存して
いない（＝この問題を E2E は検出できない）。

### 最大のリスク

**M3d が事前登録バー（`separation_margin.min_same_minus_cross_margin: 0.15`）を
通らない可能性**。Phase 0 スパイクでは異曲ペア類似度の最大値（0.8）が同曲ペアの
最大値（0.75）を上回り分布が完全重複していた。通らなければ evidence_thresholds は
永久に `uncalibrated` のままで M4 は永久に点灯しない。その場合は **melody トラック
全体を「現行の計器では測定不能」として closeout する**判断（structure 欄を dead と
した #170/#171 と同じ規律）を用意しておく。
