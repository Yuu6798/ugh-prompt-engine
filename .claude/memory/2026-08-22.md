### Design Decisions

**1. AF0 を候補選択から排除した修正が結論を反転させた（最重要）**

rev1 は候補選択の合格条件に AF0 評価を含めており §12 違反だったが、これは
規律違反にとどまらず **結論そのものを偽っていた**。AF0 を除外した calibration
から求まる energy の global gain は **−0.3431 dB**、対して AF0 の実誤差は
**−2.99 dB**。**WORLD のゲイン差は水準依存で定数ではない**ため、「global gain
を 1 個決める」という E1 の設計前提が実測で崩れている。rev1 は「AF0 で合う」
ことを根拠に operator を採用でき、見かけの成功を作っていた。

**2. D1 による AG-α 改善は「観察」であって「成立主張」ではない**

Stage C（trait-by-trait）では afterglow が fixture で 81–84 ms 残して不成立
だが、Stage D（combined D1+E0+A0 を AF0 へ）では **worst 0.88 ms で PASS**。
D1 の境界保存分割が副次的に残光の滲みを抑えていると読める。**この観察を
根拠に候補を作り直すことは行わない**（結果を見てからの候補追加 = §36 禁止）。
T0-G5 は FAIL のまま据え置き、次 revision の設計材料として Appendix C-9 に
記録した。テストで「G5 が FAIL のままであること」を pin してある。

**3. source-free 監査の偽陽性は allowlist を広げず書き出し先を寄せて是正**

第 9 巡で source-free を「宣言」から「実測 tripwire」へ変えた結果、**実際に
tripwire を走らせた最初の run（第 3 回）が violation 564 件で FAILED** に
なった。全件分類の結果 **外部音源ゼロ・`network_attempts` 空**で、
(a) 自分が数ミリ秒前に書いた PCM16 の読み直し 550 件（`evaluate_config` の
3 箇所が `publish_dir` を渡さず `tempfile.mkdtemp` にフォールバック）、
(b) `pkg_resources` の配布メタデータ走査 14 件、の 2 種の偽陽性だった。
**allowlist を広げるのではなく書き出し先を監査済み tmp 配下へ寄せる**方向で
是正し（監査境界を緩めない）、メタデータは `*.egg-info/` `*.dist-info/` 配下の
既知名に限って許可し attestation に明示宣言した。形質・operator・許容値・
選択規律は不変で、第 3 回と第 4 回の**実験側 Gate は完全に同一**。

**4. レビュー打ち切りの判断（第 12 巡）**

bot レビューが **TOCTOU / provenance hardening 1 系統で発散**した。対象が
P0 成果物 → AF0 spec → AF0 body → code closure → sidecar → T0 criteria と
1 つずつ移動し続け、CLAUDE.md §3-4 の「同一領域 3 巡」を大幅超過。加えて
第 10 巡で入れた closure pin 機構により**コード変更が canonical run の
再実行を強制**する構造になったため、第 12 巡で打ち切り、**境界宣言 7 件**を
各スレッドに次 revision への申し送りつきで残置した。
