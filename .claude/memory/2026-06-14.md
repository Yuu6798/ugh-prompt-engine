### Design Decisions
- **目的2（再現実証）= R 系列**: 既存 Q/C/K/T を新フェーズ ID で再発明せず、
  双方向再現性（`往復保存性 ≈ grip × 校正 × 採譜`）を実証する**上位ロードマップ**
  として R0–R5 を定義。各 R は T/K/Q/C の成果物を依存入力として明示。R0=T2 昇格、
  R2=Q1-3 連動、R4=T3/急所1（事象欄）。
- **再実行可能 corpus の membership 基準を「解決可能性」で一般化**: Codex が
  「stored audio 必須→ロケータ必須→fetchable 必須」と段階的に指摘（8 ラウンド）。
  保存形態を列挙すると regress が続くため、「ロケータが文書化実行環境で解決でき
  ハッシュ一致音源を取得できること」を唯一の membership 基準とし、解決不能レコードは
  観測ログへ降格、と原理化して打ち切り。
- **bpm フォールバックを完成契約へ伝播**: 完成定義 §4（bpm 含有を断定）と R2 完了基準
  （不可の逃げ道）の矛盾を、「不可なら明示除外＋理由記録」（未確定でなく除外確定）に
  統一し R3/Goal2 状態を一意化。
- **stale spec は実装実体に合わせる（Q1-3 の横展開）**: roadmap が名指しする実装の
  mechanism/symbol を code と突き合わせ、乖離は doc 側を直す（実装は pin 済みなので
  書き換えない）。Q1-2・Q1-4 の 2 件を検出・修正。
