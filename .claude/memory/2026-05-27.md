### Design Decisions

**壁打ちで到達した3つの理論的結論（未反映 — 次セッションで docs に追記）:**

1. **層間の従属関係: チェックしない**
   - 音楽はコードと違い「矛盾」が表現になる（例: BPM 60 で躍動感）
   - 層間整合性チェックは作曲の表現空間を狭めるため、やるべきではない
   - 作曲者の意図を無条件に尊重する

2. **delta_e の帰属: semantic 層に置く（現状維持）**
   - delta_e = 仕様（曲全体の感情の方向性）
   - structure = 実装（delta_e を実現するセクション構成）
   - Layer Manipulation（PoC 3）で「delta_e 固定 + structure 変更」が意味のある操作になる

3. **Score の最小成立条件: PoC は全フィールド required**
   - 書きかけ YAML の保存はファイルとして可能（バリデーションが通らないだけ）
   - Optional 化は PoC 後の UX 改善として後段に回す

**「AIは演奏者」メタファーに関する壁打ちの到達点:**

- Score が曲の 20-30% しか決めていないように見えるのは Score の問題ではなく生成器の問題
- Score は曲を 100% 定義しており、生成器の読み取り能力が不足しているだけ
- ギャップはレンダラ側の進化で閉じる問題であり、Score 側は今から完成形を目指せる
- PoC 段階では dropped_elements 等で「理想と実態の乖離」を可視化すること自体に価値がある
