## Design Decisions

### M2e-r4（校正フェーズの決裁・判定）

- **P=1 校正の 29 セル打ち切りを承認**: §8.4 の要求（2 波=2P セル）に対し 14 倍超。
  P=1 の T_stem は地図の入力ですらない（校正は production P で測る）ため、残 51 セル
  は意思決定情報ゼロと判定。
- **A 節検証 3 点**: A-1 精度スポットチェック=343 レコード判読で系統誤差 3 経路
  （時間軸オフセット/resample/stem 取り違え）をすべて棄却（MCE 中央値 3.5–4.0¢、
  外れ値は M2d 既知のオクターブ混同型で clip 固有）。direct の VFA≈0.54 は +12dB で
  既に飽和＝破断曲線の軸としては stem 側のみ有意、と判読を dated 記録に指示。
  A-2 遅延ロード確定 → **S 補正は「定義改訂でなく測定方法の §8.4 定義への一致」**と
  整理（S_corrected = プールギャップ + 初 stem 超過 + **初 direct 超過も算入**、
  T_* は per-worker で両アームの初回セル除外、キャッシュ状態依存につき保守側採用、
  セッション毎に S 再導出）。A-3 n_max は pin 済み確認のみ。
- **並列不変性ゲート**: P=1/P=3 store の共通 49 セル sha256 全一致で合格
  （既存レコードの est_trajectory_sha256 再利用を承認、回し直し不要）。
- **§8.8 決裁 #1（R_max）**: P=4 swap 失格・P=3 で N_shards≈14-15 > R_max=12 が確定
  → 選択肢 1（R_max 12→18）採用。選択肢 2（環境変更）は 2.2× インスタンス分散の
  ギャンブル、選択肢 3（clip 削減）は VM 都合で科学を削る本末転倒として棄却。
- **P=2 降格**: P=3 の direct 劣化 2.03×>1.5（§8.3 飽和判定）。P=3 の方が実効 1.4h
  速い事実はあるが、凍結規則を実測後に曲げない。
- **§8.8 決裁 #2（条件付き）**: P=2 実測（direct≈57.4s/stem≈310.5s 壁時計）から
  N_shards≈19–21 > 18 の再超過を予見し、往復を畳む条件付き決裁を User が承認:
  **「S=337.4s + T_*(P=2) で地図生成、N_shards ≤ 22 なら R_max = N_shards+2 で
  自動進行、超過なら差し戻し」**。停止条件=P=2 で direct 再超過（→P=1≈50h、
  環境変更の再検討局面）/ ゲート不一致 / N_shards>22。
