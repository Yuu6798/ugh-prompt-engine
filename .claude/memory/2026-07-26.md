### Design Decisions

- **証拠チェーンの三段階**（第 20-24 巡）: 環境 pin 再計算（導入証明）→ 評価器
  自身の測り直し bit 一致（実行証明）→ repeat ごと新規プロセス（run 間決定論の
  実証）。repeats 契約の根拠を提出物から evaluator 側の独立実行へ移した
  （決定論下ではコピーと本物の再実行は観測不能に等価、が論拠）。
- **信頼境界の運用**: 「明示 chmod / プロセスメモリ書き込み / 履歴を書ける
  同権限者」は防御対象外、と各返信で一貫宣言。境界の内側（0644 への素の write、
  chmod 不要の in-place 上書き）は採用して塞ぎ、外側（chmod 復元攻撃）は反証。
  git 立証も「blob が HEAD 祖先に存在」までを証明とし、committer date は
  `ordering_is_proof: false` の正直会計に降格（GIT_COMMITTER_DATE で偽装可能）。
- **実行形態の構造的検出**: 直接パス script は .pyc を使わない（CPython 仕様）
  ことを軸に、`__name__ == "__main__" and __spec__ is None` で `-m`/import 実行を
  publishable から排除。子プロセスには PYTHONPYCACHEPREFIX + DONTWRITEBYTECODE で
  ソース強制再コンパイル。
- **実測で掘り当てた事実 2 件**: (1) libsndfile は float WAV の PEAK チャンクに
  壁時計タイムスタンプを書く（同一波形でも bytes が秒単位で揺れる・offset 60 の
  1 byte 差を実測）→ 自前の最小 RIFF/float32 直列化で決定論化。(2) mir_eval の
  `raw_chroma_accuracy` は est_voicing を使わない（MIREX 規約）— 第 19 巡の
  P1 を実ソース+実測で反証した回。
- **コンテナ再起動対策**: 全件スイート（~20 分）が再起動で 3 連続中断 →
  ファイル単位チャンク実行 + 完了マーカーで再開可能化（以後の標準運用）。
