### Design Decisions
- **スキーマ形状**: コード進行は `events.chord_progression: List[{root, quality}]` の構造化
  リスト（文字列 DSL でなく）。root は `CHORD_NAMES`（sharps のみ）語彙に validator で固定し、
  R4-3 の `ChordEvent.root` 照合と単一語彙源にした。
- **transpose 意味論**: degree offset を **pre-transpose tonic 基準**で算出し、`style.transpose`
  は take 摂動として frequency 段で上乗せ。FAITHFUL_TAKE(t=0) で authored 絶対 root を厳密復元、
  FIRST_TAKE で進行ごと移調 → take 比較が成立。
- **比較器統合（user 指定）**: 薄い新比較器を作らず既存 `roundtrip/compare.py`（`chord_sequence_match_rate`）
  + `roundtrip/diagnose.py`（`_diagnose_chord_progression`）に組み込み。閾値 `CHORD_MATCH_THRESHOLD=0.75`
  は比較器側に置き Pydantic model に埋めない（event_roundtrip.md §校正基準）。
- **回帰安全**: chord 欄は `source.events` 非空時のみ report に追加 → 既存物理 7 欄 source の
  report 形状を不変に保つ。
- **honesty 規律**: grip fixture に chord grip record を捏造しない。record 不在時は
  `grip=None`/`grip_class=None`、knob_dead は既存 grip_map 経路を温存（knob 生存の根拠は
  R4-2 の grip テスト）。chord grip の fixture 実測化は follow-up に defer。
- **移調不変形レポート**は別レポートとして follow-up に defer（主指標は絶対 `{root,quality}` 系列）。
