### Design Decisions

**素材の relocatable rematerialization（User 裁定 2026-08-21）が本セッションの山場。**
S2 走行機の絶対パス（`/tmp/claude-0/.../2710359b-.../scratchpad/acq/...`）が失われて
おり、初回 Phase A は G0-4 で BLOCKED。裁定「『同じ絶対パス』は再現条件ではない。
『同じ archive と同じ再構築 pair』が再現条件である」を受け、**凍結 manifest を
書き換えず走行時メモリ上でだけ new root へ写像**する経路を実装した。

- 検査は archive SHA + **展開物の集約 SHA**（`pr_manifest.aggregate_extracted_sha256`
  = 相対パス + 内容）。後者は絶対パスを含まないので別 root でも同値になり、
  archive SHA だけでは検出できない「展開後の 1 ファイル差し替え」も落ちる
- **裁定 7 が実測で確認された** — S3 replay の `sample_sha256` が byte 一致
  （`1cdf3e2b…` / `0b7d43d0…` / `72eb1307…`）。別 root・別コンテナで再構築した素材が
  S3 canonical を完全再現した
- 500 エラーの原因は **folder id を file id として叩いていた**こと。`source_manifest`
  の `download_origin` にある `1XA2cm3...` は Drive フォルダで、中の
  `「波音リツ」歌声データベースVer2.0.2.zip` = `1kXkbOit...` が実体。「network policy で
  取得不可」と一度誤報告した
- Ritsu 展開では利用規約 第9条4 に従い楽曲データ 330 件を除外（S2 の台帳と一致）

**記録すべき縮退を 1 件発見（`observed_but_out_of_scope`）。**
`note_split_mae_ms` は F0 トグルに**完全に不感**で、全 6 pair で

§9.2 の Duration 側増分は §9.1 の単独増分と数値的に同一で、`duration_retention` は
