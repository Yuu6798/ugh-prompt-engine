## Design Decisions

- **最小主義境界を doc 明記**: status 自動更新なし・roadmap/STATUS 置換なし（叙述禁止・
  ポインタのみ）・重み付け/可視化なし・config 二重コピー非同梱（docs 側配置で負債回避）
- **status 語彙 5 値 + 境界記録の対称規約**: dead⇒reentry 必須・partial⇒note 必須
  （レビュー第 2R で対称化）。blocked は stored でなく導出（不整合の構造的排除）
- **frontier 意味論**: untested かつ非 blocked かつ直接依存が全て verified/partial
- **ルート claim の縮小裁定**（第 2R）: 依存追加で blocked 化せず claim を Score-level
  identity へ縮小 + note で聴感/人間同一性を範囲外宣言 — false-ready と情報消失の両方を回避
- **レビュー採否は実害基準を維持**: 第 8R で「空実質メタデータ文字列」ファミリーを
  claim/note/reentry 全数掃討し**終端宣言**（AGENTS.md §3 準拠）
- **第 4R 以降の Codex はデータ正確性監査に転じ 6 件連続的中**: 全件を一次ソース照合で
  採用（M2e r4–r6 完了の stale 訂正 → さらに r7 blocker 停止中へ再訂正 / structure grip
  のチャネル帰属（section_tags 未実証・実測は MusicGen 散文経路）/ fixity と corpus
  audio_sha256 pin の機構混同分離 / 往復診断 4 値化 / control.key verified→partial 降格）

#### Task 2: Intent Graph ループ 1 周目 — intent.ai_score の E2E 受け入れ条件定義

**根拠**: `svprpe intent-status` の frontier 出力（依存 7 ノードが全て
verified/partial で充足済み）。

- **対象 claim**: 「AI が楽譜を著述し決定論演奏者で検収し Score-level identity
  保存（sidecar 会計）まで一気通貫で実証されている」
- **Design Memo で決める 4 点**:
  (a) 経路固定 — L0a 契約準拠の著述（validate 通過）→ compose/perform →
  extract → score-adherence + AR sidecar 検証、の CLI 列と順序
  (b) 受け入れ条件 — どの計器のどの値で pass とするか。既存 verified ノードの
  実証帯域内に収める（新規計器を要求しない）。partial 依存（key・structure）は
  その note の境界内でのみ主張
  (c) 素材 — 合成 fixture で完結させ machine 非依存に設計（外部生成器を経路に
  入れない = Score-level の定義に忠実）
  (d) 成果物 — E2E テスト + dated 記録 = intent.ai_score を untested→verified
  へ遷移させる evidence。台帳更新は PR レビュー経由・一次ソース照合則を適用
- **範囲外（触れない）**: melody 軸（blocked・m3d 恒久）・聴感/人間同一性
  （ルート claim の note で範囲外宣言済み）・外部生成器の grip
- **分業**: Memo = Fable / 実装・実行 = Sonnet / 判定 = Fable
