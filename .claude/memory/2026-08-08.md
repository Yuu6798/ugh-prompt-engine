### Design Decisions

- **R2 二分割案の棄却→evaluator material 別会計**: Codex 指摘(synth の not_comparable が real 由来の
  凍結提案まで全拒否)への当初対応 = manifest 二分割は、実装検証で `_validate_manifest_composition`
  の素材構成契約と両立しないことが判明し撤回。単一 98 対 manifest 維持 + evaluate 側で pair_id
  マーカー(`_real_`/`_synth_`、ちょうど 1 個を要求)により real=校正の唯一入力 / synth=診断専用
  (`material_accounting`)へ分割。サブエージェントが矛盾を検出して停止→設計転換の好例
- **同一バイト原則の全面適用**: 「hash したバイト = パース/デコードで消費したバイト」を builder・
  harness の全入力に段階的に強制(YAML/JSON 単一読み・digest キャッシュバイパス・最終形は vocadito
  スナップショット束縛 = harness `_freeze_audio_copy` と同型)。第 3R での境界宣言(インメモリ化は
  リスク過大)は、第 12R の安価な処方(スナップショット)提示を受けて撤回・採用
- **pin 検証の強制化チェーン**: --check-only(任意)→ ハーネス強制 preflight(publishable run で
  --pins 必須)→ 凍結コピー照合(消費バイト束縛)→ evaluate の preflight 証跡要求、で run→evaluate
  の全段が fail-closed 連鎖
- **事前登録の実測前是正 2 件**: (a) rhythm 負例 fixture が log2 比表現(テンポ不変)下で構造的に
  無効 → フレーズ内長短交互パターンへ再設計 + 「診断が成立しうる fixture であること」を機械アサート
  (b) crepe 起動数会計がファイル基準の誤算(180)→ pair 基準へ全面訂正(tuning 264 + holdout 196 =
  460、半減 fallback 292)。観測キャッシュは不採用(正しさリスク > 計算節約)
- **採否は全 29 件を実害基準で個別判定**: 採用 28 + 境界宣言 1(後に撤回・採用)。不採用にしたのは
  「marker 無し pair_id の後方互換受理」(別会計 fail-closed を崩すため。代わりに検証を run 前へ前倒し)
