### Design Decisions

- **suno の structure 散文は demote でなく omit**: dead の実測（chance floor 正確一致）
  は「欄の存在目的が実現されない」ことを意味し、#153 の descriptor フラグ前例
  （`omit_structure_prose`）に従い候補にすら入れない（dropped_elements 非計上 =
  omit ≠ drop accounting）。advisory 1 件で透明化。musicgen/external は不変
- **section_tags は実験チャネルとして新設**: grip 未実証を docs/fixture に明記、
  config 化しない（YAGNI・efficacy 実証後）。None 時はシリアライズでキー省略
  （既存 backend の JSON 出力バイト不変を優先。docs の null 記述は Codex P3 で是正）
- **structure4 発注書は non-canonical 事前登録**: 時刻粒度（分単位）で均衡ゲート
  検証不能というバッチ 3 の教訓を設計段階で適用。instrumental 固定・A/B の style
  prompt バイト一致（155 字）・差分は Lyrics 欄タグのみの直交設計
- **M1 の canonical は新経路**: ABBA/均衡ゲートは「人手 UI 生成の時間ドリフト対策」
  であり、決定論 seed のローカルスクリプト生成にはドリフト機構が不在 — と**生成前に
  事前登録**した上で、Codex 指摘（「同一プロセス」は事実誤り = 実態は 16 fresh-process）
  を受けて根拠を実態へ是正し、時間的に最遠の 2 クリップ再生成 sha256 照合 **2/2
  byte 一致**で「出力は壁時計順序と無関係」を M1 内実測証拠化。Suno バッチを
  confounded/保留に追い込んだ時刻粒度問題を構造的に回避する前例になった
- **比較主張の格下げ（Codex P2 採用）**: プロンプト欄順は backend の control_defaults
  ティア順で決まる（suno=bpm tight 先頭 / musicgen=brightness tight 先頭）ため
  「生成器のみ交換」は過大 — 「end-to-end バックエンド経路比較」へ縮小し、帰属
  （機種か整形か）未分離を明記。byte 一致プロンプト再生成は製品経路と乖離するため不採用
- **append 三重硬化（Codex P2 ×3 全採用）**: 生成前検証の前置（WAV を書く前に
  fail-fast・共有ヘルパーで merge と一本化）→ revision pin 必須化 + サンプルレベル
  混合拒否 → pin を不変コミットハッシュ（40 桁 hex）に限定。HF 解決値の生成前比較は
  preflight へのネットワーク依存を理由に不採用
- **M1 判定の設計反映**: `omit_structure_prose` は musicgen へ展開しない（False 維持）
  — 根拠を「実測なし」から「実測 loose につき送出継続」へ更新。structure は
  control_profile 許可キー外のため config 反映なし
