### Design Decisions
- **二系統 manifest の関係整理**: 箱（pydantic `RoundtripTake`、`corpus_batch`/`svprpe
  roundtrip-corpus` が消費）と screen snapshot（`fetch_corpus` が raw 読み）が分離していた。
  箱を canonical 化し、screen の 7 本（+除外 wafu）を箱の `takes` へ移植。snapshot は findings
  記録として残置（将来の一本化は未解決判断として保留）。
- **`RoundtripTake` スキーマ拡張**: `extra="forbid"` のため `drive_file_id: str|None` /
  `excluded: bool` を追加。どちらも **screener 経路専用メタデータで `classify_take`/
  `corpus_batch` 非依存**。committed audio_locator が無い実音源 take は従来どおり
  observation_log（archived `measured` を replay）で一様扱い＝corpus_batch ロジック変更ゼロ。
- **honesty 規律**: `prompt` は snapshot に verbatim 生成プロンプトが無いため「screen 由来
  サマリ」と明記（捏造回避）。`measured` は screen が**実測した値のみ**移植し、未計測の
  `time_signature` は intent から除外して notes に理由記録（観測されていない非保存を
  誤って示唆しない）。`match` 値はコードに再生成させ手書きしない。
- **Codex P2 対応（案1採用）**: コミット済 CC0 fixture（synth-05、repo 相対 audio_locator +
  有効 hash）が空 drop で `not_found` になり screener から漏れる件。「out of scope と
  assert する案2」でなく「**repo-root 相対 locator を解決する案1**」を採用——synth は唯一
  フル再現可能な行で、外すより解決する方が PR の主旨に沿い pydantic 側 `resolve_audio_path`
  （ROOT 相対）とも整合。`find_locator_candidate` を `[source_dir, ROOT]` の順に解決し
  sha256 pin は解決後に再検証（wrong-hash repo hit は依然 `sha256_mismatch`）。
