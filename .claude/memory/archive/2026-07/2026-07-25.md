### Design Decisions

**1. 探索する場所は「そのモデルが実際に読む場所」だけ**
独自の探索パスを持たず torch ネイティブの `TORCH_HOME` に一本化。API 経路は
`torch.hub.get_dir()/checkpoints`、CLI 経路（子プロセスは親の `set_dir()` を継承
しない）は env 由来解決。pin とモデル入力の乖離を作らないことを最優先し、
「reference somewhere demucs doesn't read」になる案（`repo=<dir>` 渡し等）は不採用。

**2. 閉包は「実行される実装」まで広げるが、OS 基盤で線を引く**
抽出器本体 → 実行 backend（TF / torch）→ 本層が直接呼ぶ前処理（librosa / scipy /
numpy / soundfile）→ librosa 経由で必ず走る数値バックエンド（soxr / numba /
llvmlite）→ Viterbi デコーダ（hmmlearn）→ デコード実体（libsndfile、FFmpeg 実行
ファイル + `libav*`）まで含めた。**線は「本層のコードが直接呼ぶか」「デコード/推論の
実装そのものか」**で引き、libc/libm 等へ広げない（環境全体が推論スタックになると
どの環境でも fail-closed になり誰も守れない線になる）。

**3. 時点の正しさ＝「hash した bytes が実際に実行された」保証**
- `find_spec` で **import を起こさずに** digest を確定（`import_module` だと hash より
  先に cache される窓が開く）。bind をハーネスの **import 列より前**へ移動し、
  `utils/hashing.py` の numpy を関数内 import に落として閉包を numpy フリーにした。
- 推論前に pin → 推論後に **memo 迂回で再 hash** して一致を検証（size/mtime 一致の
  差し替えも検出）。分離側は checkpoint **選択集合の再解決**まで比較。
- in-memory cache（CREPE のプロセス global モデル、import 済みモジュール）対策として
  **load-time pin**（最初に観測した digest）と照合。
- システムライブラリの解決に **dlopen を使わない**（`CDLL` を捨てても mapping は
  残るため「実行は旧コード / 指紋は新 bytes」の窓が開く）。ローダと同じ探索順
  （RPATH（RUNPATH 無い時のみ・依存の依存へ継承）→ `LD_LIBRARY_PATH` → RUNPATH →
  `ldconfig` キャッシュ）をパスだけ辿る。

**4. 曖昧なら fail-closed、ただし「正直会計」で**
覆えないものを「依存なし / 揃っている」と主張しない: 非 ELF バイナリ・展開不能な
ローダトークン（`$LIB` / `$PLATFORM` は**ローダが決める値**なので推測しない）・
audioread フォールバック・部分被覆（導入済みなのに hash 不能）は route 単位で
`unavailable`。一方、実行されていないものを pin したことにもしない（API 経路 +
FFmpeg 不在は covered から外して続行 / Melodia は重みを持たないので
`extractor_weights_kind: library_binary` と明示）。

**5. 記録が scoring に接続する**
`registry.yaml` の `provenance.model_weights` を dated 記録欄へ構造化し、**記録済み
（非 null）の sha256 / version / code_sha256 は評価器が report 行と一致要求**する。
未記録は `null`（プレースホルダ文字列を pin と誤認させない）。

**凍結値は不変**: `observation_gate` 閾値と `m1_real_go_bar`（≥3/4・偽陽性0・n≥2）
には触れていない。実行時 DL 経路・リトライ・ミラーの新設なし、波形/stem の commit
なし、`pyin_direct` 単独 Go を本 Go 扱いせず、`inconclusive` を No-Go と読み替えない。

### Handoff

1. **M1-real 実測（machine-dependent・最優先）**: 機械独立な配線は #216（バー+評価器）
   と #217（ゲート+emit）で揃った。残るのは実測のみ —
   (a) 重みを事前取得して `.[separate]` を導入（docs §6.4 のレシピ）、
   (b) `describe_separation_weights()` で version/sha256 を採り registry の
   `provenance.model_weights` へ記録、
   (c) 凍結素材の `expected_audio_sha256` を registry へ記録、
   (d) `--external` で実測 → `evaluate_m1_real_go_bar` を機械適用。
   **1 run = 1 プロセス**で回すこと（load-time pin と in-memory cache の対応保証）。
   **M2 へ自動進行しない**（明示 Go 判定要求）。
2. **分離 pin の適用範囲は現状 Linux/ELF 限定**。macOS/Windows は依存 closure を
   読めないため分離経路が `unavailable` に落ちる。Mach-O / PE parser は未実装（必要に
   なった時点で判断・「読めなかった」を「依存なし」と主張しない現状の扱いは維持）。
3. **入力形式の制約**: 観測対象は pin 済み soundfile スタックで読める入力に限定
   （AAC/M4A 等は fail-closed）。Suno 素材を WAV/FLAC で回収すること。
4. **経験外部化の候補**（§7 で User へ提案・下記 Design Decisions 3–4 の一般形）:
   AGENTS.md §8 の emit 前チェックリスト（#203 で 7 項目制度化）に
   「pin は実行された実装に接続しているか」の 3 問（**場所**＝そのモデルが実際に読む
   場所を探索したか / **時点**＝hash と実行の間に cache 窓が無いか（import・dlopen・
   in-memory model）/ **被覆**＝覆えないものを「無い」と主張していないか）を追加するか。
