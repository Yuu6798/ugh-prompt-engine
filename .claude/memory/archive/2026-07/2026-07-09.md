### Design Decisions

- **excl 音源の同定**: 再抽出値がフラグ署名（R2-2f 発火=excl_04・octave 曖昧のみ=excl_03）
  まで判読値と一致 → 4 本を excl_01–04 に確定割当（excl_01/02 の take 順のみ再構成不能で
  便宜割当・README honesty 明記）。measurement は fixture へ、発注書 verbatim 消失は honesty 記録。
- **P2① expected_sign**: `exclude_net_effect` を観測方向 +1 で置くと net-effect の失敗が
  classify_grip 上「tight 成功」に化ける自己成就的誤り。事前登録極性 −1 を保持し dead へ是正
  （バッチ 1 `semantic_avoid` = expected_sign −1・観測 +4.03・dead と同型）。
- **P2② semantic.core config 撤回**（アーキ的に重く AskUserQuestion で User 決裁）: #162 SEM-1 の
  `semantic.core` loose 入場は grip がカスタムモデル実測（stock 一般化未検証・honesty (g)）なのに
  `external`→suno 解決で stock/external 全 render の truncation 優先度を変えていた。他ノブ
  (bpm/brightness/lyrics_presence) は stock 未検証の但し書きなし。「実測なき横展開をしない」規律
  （#153）に基づき config 反映を撤回（測定値は docs/fixture に保持・再入場は stock 検証 or
  model-scope 機構の新設後）。
- **P2③〜⑦ cross-batch 交絡（本セッションの核心的教訓）**: Exclude 追試は excl セル
  （モデル/フロー未確認のブラウザ生成）と baseline（batch-1 user-custom 流用）を跨ぐため、
  d=−1.66/+1.64 は Exclude 欄効果と generator/model/batch drift を分離できない。§7.6「解消」を
  「未確定」へ格下げし、全 docs（controllability_poc.md 比較表/caveat・musicgen_backend.md §7.6・
  control_profile.md・README・excl_plan.yaml・**tests/test_grip.py docstring**・PR 本文）で
  「効く/打ち消せない/留保解消」の断定を交絡明記 or batch-1 論拠へ統一。**比較2 の dead も交絡**
  （前回「交絡非影響」と書いたのは私の誤り＝+1.64 の明化自体が明るいモデルで説明可能）。
  batch-2 structure 設計も同型の cross-batch 交絡を抱えていたため、**同一バッチで low+high を
  両生成する隔離設計を primary**に是正（batch-1 calm 再利用の経済化は confounded と pre-mark 必須・
  事後判断での low 再生成は否定）。**omit_body_negative(#163) の妥当性は batch-1 内実測
  （calm vs calm_avoid・同一モデル・d=+4.03）に立つため交絡と独立して無傷**。
