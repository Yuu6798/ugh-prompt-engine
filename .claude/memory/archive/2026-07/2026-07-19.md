### Design Decisions

- **「人手生成律速」の解体**: AR4 実測は queue 上 Suno 人手待ちだったが、
  #136/#171 前例の MusicGen ローカル決定論路線で無人化（12s→30s の 2 バッチ、
  fresh-process sha256 2/2 一致、canonical 規律の事前登録付き）。「律速」は
  検証すべき仮説であって所与ではない、が今日の最大の方法論的教訓
- **AR2-3 の解凍 2 段判定**: #191 時点では保留継続（form anchor 不在・12s は
  form 表現不能）とし条件を (a) センサー配線 + (b) 長尺 form artifact に具体化 →
  同日 #193 の 30s 実測で (b) 充足を確認し解凍。「実測が揃うまで設計しない」を
  同日内で 2 回誠実に運用した
- **AR2-3 本体の設計核**（new-brief skill 経由の Design Memo・#194 は Codex
  指摘ゼロ = 理想の 0 ラウンド）: stable ID は form 文書（section-map/0.2）自身が
  持つ / センサーは 0.1・0.2 の明示的二形式（committed 観測 fixture の再現性保全 =
  fail-fast 置換流儀の根拠付き例外）/ section_ref は 0.2 anchor の id へ解決・
  0.2 不在時は opaque 後方互換 / 変形語彙は実測 3 現象（挿入・欠落・反復）に
  1:1 対応の 3 語のみ追加（未観測の reorder は追加しない）
- **Codex 対応の収束パターン**: #191 の 9 ラウンドは全て「committed provenance
  成果物のマシン非依存・全入力の pin 検証接続」という同一ファミリー。逐次対応で
  外側から閉じたが、最初に「レシピの全入力を package pin に検証で接続してから
  emit」と設計していれば 1-2 ラウンドで閉じた（§8 候補として下記 Handoff）
- **日付事故と是正**: Memo 日付を 2026-07-20 と誤記し decision trail に混入
  （Codex P2）。実クロック（生成タイムスタンプ・authored date）は全て 07-19 UTC。
  是正時、hash 連鎖が pin する manifest 内コメントの誤日付は**意図的に残置**
  （コメント正誤より hash 連鎖保全を優先）
- **正規化規則の 3 ラウンド収束**（#192）: 末尾数字 strip を全ラベル → 語彙限定 →
  **非対称（正典 verbatim / 観測は抽出器の VerseN 慣行のみ吸収）**へ。「作者の
  識別子を計器が潰さない」が最終原理。5 語幹案は当方設計の過広で透明に撤回
