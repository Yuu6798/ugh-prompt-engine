### Design Decisions

- **指示書内矛盾の裁定**: §5「mode_overrides を suno.yaml に追記」vs §8「既存 sidecar スキーマ
  変更禁止」→ §8 優先。recast 所有の新 config `mode-overrides/0.1`(cover/prompt_only 別の
  field 可否、Cowork 実測 2026-07-17〜19 n=4×2 を evidence 収載)+ project からの明示参照
- **Phase 0 ゲート不成立の適用**: melody は「センサー配線あり・弁別不成立」を正直に扱い、
  観測は既存 D-1 経路(exact match のみ preserved)。E2E 実測でも harmony/structure とも
  not_observed/deferred(harmony=2 サイクル一致後尾部乖離、structure=位置一致率 0.375)=
  「約束するのは測定できるものだけ」の実装実証として承認
- **状態機械**: recast-state/0.1 に (variant,backend) 単位で永続化。plan は診断=入力不変なら
  進行状態(awaiting_generation 以降)を降格させない。設定エラー(unknown anchor 等)と
  観測実測失敗(observation_incomplete)を状態レベルで区別
- **pin の網**(Codex レビューで確立): inputs_digest(選択 run への射影・observation 節除外)/
  plan_sha256(per-run 正典 `<builds_root>/plans/<v>@<b>/`)/ orders_digest(注文書 6 ファイル)/
  take sha256 / package sha256 / observation_digest(observed/reported 専用の二層 pin)。
  全て「読んだ bytes=使う bytes=pin する bytes」の single-read 束で貫通
- **公開規律**: 全公開サイト(orders/takes/packages/plans/report)は staged 一括
  atomic+BaseException rollback+protected_inputs 衝突ガード必須引数+preflight。
  書き込みは encode 1 回の bytes 経路(CRLF 乖離根絶)
