### Design Decisions

- **#184 provenance P1**: bundle outputs を `{path, sha256}` 化（bundle schema 0.2）、
  compiler 記録（package_version/schema_version/git_commit）、content_digest と
  invocation_provenance の分離、不変 `builds/<content_digest>/` dir、pathsafe utility 共通化
  （lexical/resolved 分離）。レビューで Windows 式遡上拒否・builds descriptor の digest
  自己整合検証・latest.json 衝突ガード・既存 digest の read-only 照合を追加硬化。
- **#187 AR4 = `svprpe observe` + observation report sidecar**（計器であって verdict なし）。
  17 ラウンドの主要な積み上げ: chord artifact の fail-closed（非リスト値拒否・検証済み
  バイト列持ち回り）、TOCTOU 排除+出力衝突ガード、単一和音正典での `_cycle_alignment`
  無限ループ修正、work_id / anchor id 集合の provenance 突合、observation-report/0.1 の
  status 語彙を発行実態へ narrow + schema_version 必須化、音声スナップショットの配線済み
  センサー述語 gate 化 + tempfile OSError の整形ハンドリング統一（`Error:` + exit 1 +
  best-effort 掃除）。
- **observe の検証境界の線引き（round 16 却下・User 承認済み）**: Codex が round 10→15→16 と
  package の各フィールドを 1 ラウンド 1 件ずつ「改竄されたら」観点で突合追加を要求する
  発散パターンに入ったため、**「observe のクロスオブジェクト検証は provenance の同定
  （manifest sha256 / work_id / anchor id 集合）まで。channel_artifacts 等 package 内部
  フィールドの内容整合は package スキーマ検証・将来の `verify` コマンドの責務」**と
  docstring に明文化して却下（`6ab4991`）。以降のラウンドは別種の正当な指摘（round 17 の
  OSError ハンドリング）のみとなり収束。**採用/却下は指摘の種類で判定する**（provenance
  深掘りの無限後退=境界で止める / エラーハンドリング統一=既存方針準拠なので採用）。
- **#186 縦切り E2E はレビュー指摘ゼロ**: 実在 artifact 1 つで
  manifest→contract→profile→package→report を一気通貫。既存部品の結線のみで新規面を
  作らなかったことが指摘ゼロに直結。
