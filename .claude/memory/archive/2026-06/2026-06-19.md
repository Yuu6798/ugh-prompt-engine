### Design Decisions
- **スキーマ形状**: コード進行は `events.chord_progression: List[{root, quality}]` の構造化
  リスト（文字列 DSL でなく）。root は `CHORD_NAMES`（sharps のみ）語彙に validator で固定し、
  R4-3 の `ChordEvent.root` 照合と単一語彙源にした。
- **transpose 意味論**: degree offset を **pre-transpose tonic 基準**で算出し、`style.transpose`
  は take 摂動として frequency 段で上乗せ。FAITHFUL_TAKE(t=0) で authored 絶対 root を厳密復元、
  FIRST_TAKE で進行ごと移調 → take 比較が成立。
- **比較器統合（user 指定）**: 薄い新比較器を作らず既存 `roundtrip/compare.py`（`chord_sequence_match_rate`）
  + `roundtrip/diagnose.py`（`_diagnose_chord_progression`）に組み込み。閾値 `CHORD_MATCH_THRESHOLD=0.75`
  は比較器側に置き Pydantic model に埋めない（event_roundtrip.md §校正基準）。
- **回帰安全**: chord 欄は `source.events` 非空時のみ report に追加 → 既存物理 7 欄 source の
  report 形状を不変に保つ。
- **honesty 規律**: grip fixture に chord grip record を捏造しない。record 不在時は
  `grip=None`/`grip_class=None`、knob_dead は既存 grip_map 経路を温存（knob 生存の根拠は
  R4-2 の grip テスト）。chord grip の fixture 実測化は follow-up に defer。

## Session Summary — 2026-06-19 Session 2

### Context
外部記事「AIに耳をつけてみた」（`MintoTsukino/ai-audio-analyzer`、MIT）の分析依頼から、
当該スクリプト `analyze_audio.py`（librosa + Whisper/PANNs/Demucs）と svprpe `extract` の
**実測差分比較**へ展開。この環境で外部 repo を clone し軽量モードを実行（librosa 系依存は
導入済・network 開放、ML 系は numpy<2 衝突 + torch 未導入で別 venv 必要）。synth 2 曲 +
**実音源 3 曲（A/B/C、user upload、非コミット）** で両ツールを突き合わせた。

### Design Decisions
- **重複コアは実測で「同等」確定**: BPM/key/onset はビット〜小数一致、centroid 小数2桁一致、
  stereo width/corr 3桁一致、LUFS は実音源で0.1dB以内（synth で出た3dB差は疎・持続音特有の
  gating 差で系統的でない → 当初「校正課題」は撤回）。true peak は自前が 4x oversampling で規格的に上。
- **★ spectral_profile の power/magnitude 不整合を発見**: 既存 3帯域は `|S|²`(power) 積算で
  低域を過大評価し、同オブジェクトの magnitude 基準 `centroid` と矛盾。high(>4kHz) が
  自前 2.4–4.4% vs magnitude 30–36%（A/B/C で再現）。`controllability_poc.md` の
  「brightness band比センサー盲（→centroid 移設済）」知見の延長＝単なる解像度不足でなくバグ性。
- **移植は additive に分割**（in-place 改変は semantic_rules/config閾値/20+テスト/screen yaml に
  波及するため）。Phase 1 = 新フィールド追加のみ・既存3帯域不変。Phase 2（再校正）は defer。
