### Design Decisions
- **R0（往復ループ / #75）レビュー**: bpm 比較器がメモ仕様 `|Δ|≤5` でなく厳密一致で、
  Δ=1〜3 の往復が `calibration_disagreement` に誤倒れ → R0-3 相互検証を歪める P2 を指摘。
  併せて grip 地図の wheel 非同梱 P3 等。**P2(±5 許容差) と P3(grip package 同梱 +
  JSON 等価性回帰テスト) は次 PR 前に main へ反映済みを確認**（synth_02 が preserved に）。
- **R5（fixity 型 + 入場試験 / #76）**: fixity 表現方法を 3 案（optional ブロック /
  派生関数のみ / R5-1 のみ分割）から噛み砕いて提示し **A 案（optional `fixity` ブロック）**
  をユーザーが選択。理由は受け入れ条件「T1 出力が which-field-locked を表現」を満たすには
  YAML 永続化が要るから。実装は `@model_serializer` で None 時省略し authored Score の
  snapshot ドリフトを防止、semantic_ci.lock との区別も doc 明記。クリーン（P3×2 のみ）。
- **R1（再実行可能 corpus / #77）**: 「箱部分」= manifest スキーマ + ローダ + バッチ +
  既存 4 ケース観測ログ化 + in-repo テスト用 calibratable レコード 1 本に scope 限定し、
  **実音源確保は人間律速トラックで OUT**。send_form（numeric_knob/qualitative_cue/not_sent）を
  field 単位で持ち numeric_knob のみ比較する設計が核心（盲目センサーの一致を制御証拠に
  しない §3 を encode）。R0 比較器を `compare.py` へ behavior-preserving 抽出。calibratable は
  committed CC0 synth wav backing で bpm 170→172 保存を決定論 snapshot 化。P3（C-gen
  brightness の send_form が §3 と不整合で bright→neutral 非保存が表から脱落）を指摘。
