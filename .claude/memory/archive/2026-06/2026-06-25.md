### Design Decisions
- **B-1 スコープ = ハーネス先行**: Phase B は「Suno 生成バッチ（人間律速）＋閾値導出」を束ねるが、
  Codex Design Memo は実装タスクであるべき。R1-audio (#94/#97) の content-addressed box-first を踏襲し、
  「コーパスを食う箱と分析器」を先に作り、データは後入れ。Suno 生成プロトコルは companion（人間作業）として分離。
- **honesty ゲート（`insufficient`）を AC 化**: seed が少数のとき「閾値が出た風」の出力を構造的に禁止。
  `n<MIN_SAMPLES_PER_GENRE(=3)` を insufficient とし閾値候補を出さない。
- **misfire 監査 = 計器、裁判官でない**: 2026-06-03 C0/C3 の audit 規律（verdict/pass-fail 禁止、
  `_assert_no_outcome_keys`）を踏襲。混同表＋記述的 `mismatch` のみで accuracy を出さない。config 解決は
  production の `generate_semantic`（`load_config`+`_backfill_genre_sections`）と同一経路に固定。
- **バイト転送制約の橋渡し**: Drive→remote 環境は MB 級 base64 をインライン転送不能（R1-audio で判明した
  制約のダウンロード方向版）。今回はユーザーがファイルをセッション添付→`/root/.claude/uploads/` から直接
  `extract`。provenance は byte-size（Drive 一致）+ sha256 でピン。

## Session Summary — 2026-06-25 Session 2

### Context

### Design Decisions
- **誤診是正 = 厚い素材を明暗で二分**: `low_ratio>0.4`（低音が厚い）を `high_ratio` 0.017 で
  二分し、暗い→`cinematic/orchestral`（管弦）、明るい→`bass-music`（EDM）。相補ルール化。
- **discriminator は brilliance(d=6.99 最強)でなく high_ratio を採用**: (1) `spectral_bands` は
  Optional で旧 RPE/手書き fixture に無く後方互換を割る、(2) Q1-5 Ph2 が power比→magnitude へ
  rule 族ごと移行する計画。B-2 は既存 bass-music と同じ power比族に留め、magnitude 移行は
  Q1-5 Ph2 へ一括委譲。high_ratio は spectral_profile 必須欄で常在＝後方互換安全。
- **synth 誤検出（Phase A 罠の再来）を起草段階で de-risk**: 起草中に test corpus synth 5本を
  実測し「暗さ単独ルールは synth(暗・centroid≈700・brilliance≈0.014)を誤検出する」を発見。
  `low_ratio>0.4` ガードで除外（synth は low_ratio≤0.139）。「snapshot 再生成なし pass」を
  AC 化して恒久ガード。これがなければ snapshot drift で複数ラウンド churn だった。
