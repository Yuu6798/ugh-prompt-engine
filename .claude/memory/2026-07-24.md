### Context

「比較器の問題ではなく入力帯×抽出器の問題」と再定義した再入）。

### Design Decisions

- **観測ゲート（M1 本体）**: `melody/observability.py`。抽出器非依存の共通中間表現
  `MelodyObservation` → `MelodyObservabilityReport`（note/phrase/被覆/信頼/オクターブ誤り/
  cross_extractor_agreement/status/reasons）。比較（M3）を一切呼ばない。閾値は M0 で
  registry に事前登録し M1 で緩めない（one_way_rule）。
- **抽出経路 routing**: `melody/routing.py`。入力種別→経路候補。旋律不在入力は
  `not_applicable`(applies=False) で抽出せず not_observed へ落とすが、診断用に
  `pyin_negative_control` も併走させ「ゲートが抽出器の false positive を弾く」ことを
  harness 出力で自己実証。
- **slow-lane / learned 隔離**: pyin だけが CI 経路（core librosa）。CREPE/Melodia/Demucs/
  basic-pitch は optional。標準 CI は重依存なしで green。抽出結果は決定論 RPE へ書き戻さない。
- **ライセンス規律（Codex round-22）**: CREPE の *コード* は MIT でも同梱重み（model-*.h5）の
  ライセンスを別途 inspect/pin していなかった→ policy §4（permissive コード ≠ permissive
  重み）に照らし、`[crepe]` published extra を**削除して Melodia と同じ manual/external 統合へ
  降格**。`_WEIGHTS_LICENSE="UNVERIFIED…"` を fail-closed で明示。重みライセンス実確認は
  machine-dependent な slow-lane 課題（Codex/User 側）と位置づけ。
- **provenance pin 網（Codex 全ラウンド通底）**: registry_sha256 の single-read 束、external
  audio_sha256 の byte-freeze、manifest_sha256、そして round-23 で **synthetic waveform_sha256**
  も registry.provenance と照合（drift を fail-closed reject）し report へ serialize。閾値
  override は asdict で「実際に使った閾値」を pin し registry snapshot の誤主張を排除
  （round-21）。公開は staging→os.replace の atomic + manifest-last。round-21 の symlink
  EXDEV は staging を out_dir 内へ置き symlink/マウント非依存の同一 fs を担保。

## Session Summary — 2026-07-24 (Session 2)

### Context

外部設計書「DESIGN_M1real_slowlane_observability.md」を Claude 完結ルートで実装し、
**PR #216 を単一トラックで完走・マージ**（branch `claude/design-implementation-9rauyu`）。
Session 1 の M0/M1 観測ゲート（#215）の続きで、**M1-real = slow-lane メロディ観測可否の
Go/No-Go バー**を機械化。核心は「実測はマシン依存の slow-lane に委ね、機械独立な配線
（凍結バー事前登録＋機械的評価器）だけを Claude が確定し、数値/verdict は捏造しない」。
Codex レビュー **20 ラウンド（指摘 #45〜#64）**をきり上げなしで対応。

### Design Decisions

- **凍結 Go バー（機械独立）**: `registry.yaml` の `m1_real_go_bar`（positive 4 + negative 1・
  ≥3/4 sufficient・偽陽性 0・n≥2）を事前登録し、`evaluate_m1_real_go_bar` が緩めず機械算出。
  3 値 verdict `go`/`no_go`（全経路実測で生存なし＝強化版）/`inconclusive`（未測定経路あり）。
- **generator provenance を import 閉包で構造化（#52・treadmill 終端化）**: 「hand-list が
  遅延 import を取りこぼす」（pyin baseline の `physical_features` 関数内 import）が #49/#51/#52 の
  反復の正体と診断。`_generator_code_paths()` を seed からの **AST first-party 推移閉包**に変更
  （`ast.walk` が関数内 import も辿る）。同集合が `generator_code_sha256`（現 checkout 一致必須・
  #55）と `--out` 保護の双方を駆動。`test_generator_code_paths_is_import_closed` で閉包不変条件を
  CI が Codex より先に守る。
- **Go バー semantics の fail-closed 強化（#53/#54/#59/#61/#62）**: 凍結素材 audio pin・Demucs
  stem/weights・学習抽出器 weights を Go 前に**必須化**し、いずれも真の sha256（`fullmatch` 全体
  一致・末尾改行も弾く）で検証。要求は machine-independent／hash の emit は machine-dependent と
  分離（CLAUDE.md レビュー振り分けルール準拠）。当面 Go 可能な非重み経路は `pyin_direct`。
- **重複キー拒否の対称化（#46/#60）**: report/manifest の JSON（`object_pairs_hook`）と registry の
  YAML（`_NoDupSafeLoader`）双方で last-wins を弾く。
- **`--out` 衝突ガードの全分岐対称化（#47/#48/#49/#51/#57/#63/#64）**: harness・generator/評価器
  コード・source audio・manifest を全モードで保護。manifest は resolve 済み絶対パスで記録（別 cwd
  評価での誤解決を防ぐ・#64）。
- **run 独立性（#45）**: 決定論パイプラインで n≥2 が意味を持つのは独立実行のみ→`run_id` を発行し
  評価器が非空 str + 相互 distinct を要求（コピー由来の偽 repeats を弾く）。

### Artifacts

### Handoff

  `expected_audio_sha256` を registry へ記録、(2) Demucs stem/weights・学習抽出器 weights の
