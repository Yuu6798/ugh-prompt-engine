### レビュー 12 ラウンドで塞いだ穴は 2 系統に集約される

すべて **「内部整合しているが、実際に走った/使われたものとは違う」** の変奏だった。

**(A) 生成物 provenance — 生成器側の保証は生成物と一緒に旅をしない**

- 混合式・入力登録簿 2 本の digest を、**測る側が自分の committed 実体と全数照合**
  （名乗るだけで検証されない経路を全部潰す）。
- `bed_id` 集合を `accepted: true` ベッドへ束縛（件数と clip 集合だけでは、任意の
  2 本のベッドで作った帯が凍結コホートを名乗れた）。slug 規約は生成器の写しなので、
  全 50 トラック名で両者一致を機械検証する。
- コホートは**絶対量**を要求（2 bed × 40 clip = 80 entry）。fixtures と manifest を
  同じだけ切り詰めると相互一致するので、矩形性検査では縮んだ帯を検出できない。
- build 中の登録簿差し替え: parse と digest を**同じ bytes snapshot** から導く。
- 混合式自身は import 時に digest を固定し、publish 直前に不変を要求（走ったコードと
  ディスク上のコードが食い違う bundle を publish しない）。
- accepted ベッド数を**生成前に**検査（320 本の WAV を作り切ってから落ちるのは高い）。

**(B) 環境同一性の被覆 — `env_digest` が「走っていない実装」を指す窓**

版 → 実装 hash → 同梱ネイティブ → 束縛時点 → post-run 再検証 → 失敗時のセル隔離、
と対称性の穴を順に埋めた。

- 数値構成 env（`OPENBLAS_*` / `NPY_DISABLE_CPU_FEATURES` / `MKL_CBWR`）を折り込む。
  リポジトリ自身が「バイト列不変のまま数値が変わる」実測事故を記録していた。
- 版文字列は in-place patch/rebuild で動かない → `packages_code_sha256` の実装 hash。
- `packages_code_sha256` は package root 配下しか覆わない → `numpy.libs/` の OpenBLAS を
  `_scorer_dist_native_sha256` で追加。
- **束縛時点**: `soundfile` は module scope で import されるので、native もコード側も
  import 前に束縛する（後から読み直すと dlopen/in-memory の旧実装で走りながら新 bytes を
  名乗る）。
- **post-run 再検証**: memoize を迂回して読み直す（遅延 import の crepe/tensorflow/
  librosa は「束縛後・import 前」に差し替えられうる）。
- **隔離**: 検査は run 末尾にしか走らないため、落ちても書き済みセルが残り、実装を戻せば
  次の run が同じ digest でそれを resume できた → この run が書いたセルを
  `.quarantined-*` へ退避してから送出（削除せず証拠は残す）。

### 自分の判断を撤回した 3 件（いずれも Codex が正しかった）

1. `env_digest` の `{None}` 許容 → evaluate を緩めるのでなく **run 側**を直した。
2. 矩形性のみのコホート検査 → **絶対量 2×40=80** のゲートへ差し替え。
3. `packages_code_sha256` の送出を理由文字列へ畳んだ緩和 → **撤回して伝播**へ。
   `_env_digest_demucs_weights` との類推が成り立っていなかった（重みが無ければ測定は
   起きないが、**導入済みで hash できない実行パッケージは実際に測定を実行する**）。

### 全面採用しなかった 1 件（理由を明記して据え置き）

ネイティブ束縛の対象集合を「選択カテゴリで絞る」案は採らなかった。絞るとカテゴリ選択の
違いで `env_digest` が変わり、**環境同一性が run の引数に依存**してセルの合算可否判定が
壊れる。module scope 呼び出しの撤去（＝素の run を落とさない）だけを採り、理由はコードの
docstring と返信の両方に残した。

### 判定の据え置き（設計 §6.2/§11 に照らした裁定）

単一 `evaluate` は 1 水準しか見ないので、M2e カテゴリは `pass`/`fail` を**出さず**
`census_pending` を返す。帯の判定を出せるのは水準横断センサス集計（**C5**）だけであり、
これを `HANDOFF.md` に未了として記録した。

### 運用上の実測知見（次セッションで踏まない）

**全件テスト実行中にソースを編集してはならない。** ハーネスは自分のコード digest を
import 時に pin して実行後に照合する（`_require_unchanged_since_load`）ため、走行中の
編集は **122 failed** という大量失敗として現れる（実体のある回帰ではない）。今回これを
一度踏み、クリーンツリーでの再実行で切り分けた。以後はレビュー対応が来たら
`TaskStop` で全件実行を止めてから編集し、ラウンドが途切れた時点で 1 回通す運用にした
（CI は各 push で独立に全件を回すので冗長性は保たれる）。
