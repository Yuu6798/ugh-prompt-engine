## Design Decisions

- **#142 key 一致判定の統一 = consolidate であって collapse でない**: 実測で key
  比較は **5 コピー・2 系統**（`compare.keys_match` の異名同音 boolean / `audit`・
  `measure_grip`・`build_k3_fixture`・`build_k3_musicgen_fixture` の mir_eval 加重）。
  boolean 系（往復の二値 verdict）と weighted 系（近縁調の段階効果量）は**意図的に
  別概念で統合してはならない**（＝負債メモの「挙動変更」リスクの正体）。真の重複は
  weighted 系 4 コピーで、唯一の差「fallback / fail-fast」を `require_mir_eval` 引数で
  吸収し `svp_rpe/keys.py` へ集約。挙動完全保存。循環 import は `perform` の関数内
  遅延 import で回避。
- **#143 CLAP 埋め込みサイドカー化 = ロスレス退避**: 巨大な `audio_embedding`
  （32×512 float=326KB の主因）は**消費側精査でアーカイブ provenance 専用**と確定
  （実計算は保存済み cosines/contrast_fit を使い、唯一のテストは非空チェックのみ）。
  → `<stem>.embeddings.json` サイドカー（text JSON・diffable/sha ethos 準拠、binary
  npz は不採用）へ既存値のまま退避（CLAP 再実行なし・数値再生成なし）。schema 1.0→
  1.1。`split_fixture`/`merge_fixture` は round-trip 恒等。Codex P2=重複 `sample_id`
  fail-fast。
- **#144 CI nightly extra = install-only（案 A）**: 実際の回帰（#138 CLAP / #139
  basic_pitch・panns・beat_this ×3）は全て「extra を入れると本物パッケージの
  version/metadata が fake テストへ漏れて割れる」型で**実推論不要**のため、重い extra
  を入れて既存スイートを回すだけで捕捉できる。Codex が 2 ラウンド追撃: (1)
  `semantic-embed` py3.11 install 不安定記録→当初 `continue-on-error`、(2) それは
  「install 失敗→サイレント緑→CLAP 回帰未検証」で安全網の意味喪失、と正当な指摘
  → **2 ジョブ分離**（`test-extras`=core は必ず緑 / `test-clap-extra`=CLAP は fatal
  だが独立ジョブで scoped に赤=可視シグナル）で決着。
- **実測 KEY FINDING（nightly 手動 dispatch, run 28695987277）**: **全 4 ジョブ
  success**。特に **`semantic-embed`(laion-clap) install は clean GitHub runner で
  3.11/3.12 とも成功**（各 ~1 分 48 秒）。→ STATUS/2026-07-03 S3 の「semantic-embed
  py3.11 ビルド不能」は **S3 の proxy 遮断リモート env 固有の friction** であり
  clean runner には該当しない、と確定。2-job の scoped 設計は無駄にならず（将来の
  install rot を局所シグナル化）、かつ CLAP カバレッジも緑で成立。
