### Design Decisions

- **sidecar-first の貫徹**: 全 6 PR で canonical `CompositionScore` を無変更（AR1-1 の ArrangementSpec も AR2-1 の IdentityManifest も非 canonical 入力/サイドカー。planning D1 準拠）。`PreservationSpec.identity_anchors` は additive optional で後方互換を CLI byte 不変まで pin
- **4 軸分離の実装着地**: fixity（採譜確定）/ preservation（編曲可否: hard・elastic・free）/ capability（入力チャネル存在: supported・experimental・unsupported・unknown）/ adherence（将来 AR4）を別モデル・別ファイルに分離。hard は「resolver における変更禁止」であって生成器保証でないことを docstring 契約化
- **推測補完禁止の一貫適用**: policy 省略の非 required anchor は contract に含めない（省略=free と解釈しない）/ profile に無いチャネルは unknown（supported にも unsupported にも倒さない）/ 変形語彙は planning 記載 7 種限定・語彙なきドメイン（lyrics/rhythm/motif）は elastic 不可（契約の空洞化拒否）/ hash は呼び出し側の明示注入のみ
- **決定論の作法**: 成果物にタイムスタンプ・絶対パス・output_dir を埋め込まない。AR1-3 の expected/ は実 CLI × リポジトリルート相対パスで生成し、2 回生成 sha256 一致を確認してからコミット（fresh-process スポット検証規律の適用）
- **Codex 指摘から結晶した頻出修正型（→ Handoff の政策提案）**: ①**path 封じ込め** — identity artifact（#178）と evidence（#180）で同型の「絶対パス拒否 + resolve() 後 is_relative_to」修正。#180 R3 で「字面（lexical）遡上判定は base 不要」（PurePosixPath 深さカウンタ）という切り分けの訂正を受けた ②**JSON 読み戻し経路の invariant safety net** — builder が保証する不変条件（mode/allow 整合・domain 語彙・anchor_id 一意）を schema validator でも強制（#179 ×2）③**多ファイル書き込みの原子性** — staging + os.replace + snapshot/rollback、残余窓=二重障害のみと honesty 明記（#176 ×2）④**packaged 配布整合** — package-data 追加 + evidence 実在検証を明示 evidence_base 限定化（既定 cwd の暗黙依存廃止。#180 ×2）⑤**hash とパースの同一バイト列**（TOCTOU、#176。以降の新 loader では設計段階で先取り済み）
- **exit code 規約の確定**: `svprpe arrange` の入力系エラーは stderr 1 行 + exit 1 統一（exit 2 は CLI 引数不正専用の既存慣習を温存）。compile 段の except は `OSError` 全体（#176 R4）
- **Scope 拡張の設計裁定 1 件**: pyproject.toml は memo で Scope OUT だったが、package-data 1 エントリ追加（依存追加でなく packaging 整合）に限って設計側で承認（#180）

### 実装契約（優先度・推奨順）

**P0（AR3-2 実装前の修正、推奨順 1–3 → 1 PR にまとめ可）**
1. **free の説明修正**（挙動不変・文言のみ）: hard=変形禁止・allow 空 / elastic=列挙変形のみ許可 / **free=変形を個別列挙で制限しないため allow 空**。現行の「hard/free permit no transformations」は free の根拠として不正確 — docstring・エラー message・docs を修正
2. **schema_version 厳格化**: `Literal["identity-manifest/0.1"]` / `Literal["preservation-contract/0.1"]` / `Literal["input-capability/0.1"]` で未知バージョンを読み込み拒否。**IdentityManifest は schema_version 欄自体が現状無いので新設**
3. **identity artifact の形式明示**: 拡張子推測禁止。`artifact_type`（許可値: lyrics_text / midi_clip / note_events_json / chord_sequence_json / audio_excerpt / section_map）+ `media_type` + `format_version` を IdentityAnchor に追加
4. **M1 表現の統一**: 実証済みは semantic.core + physical.key のみ →「意味核とキーを保持した **Score-level identity preservation demo**」に統一。聴覚的同一性・サビメロディ保持を実証済みと書かない（docs/PR 本文/チャット説明とも）

**P0（AR3-2 PerformancePackage の設計契約）**
5. **4 段階の状態分離**: requested（保持要求）/ deliverable（配送可否）/ controllable（効く根拠）/ observed（結果）を anchor ごとに別欄で持つ（推奨モデル: anchor_id + requested_mode + delivery{channel,status} + control{status,evidence} + observation{status}）
6. **状態語彙の分離**: delivery_status = delivered / experimental / unsupported / unknown / not_requested、adherence_status = preserved / changed_within_policy / changed_outside_policy / sensor_blind / not_observed。delivered・supported を preserved と同義にしない
7. **strict / advisory モード**: strict = hard anchor 配送不能でコンパイル失敗、advisory = package は生成し警告記録。**暗黙のテキスト代替禁止**（symbolic_melody unsupported → "keep the same melody" へ自動変換しない。明示 fallback policy 指定時のみ代替可）

**P1（証跡・再現性）**
8. bundle に**出力ハッシュ**追加（outputs を {path, sha256} 構造へ — bundle schema 0.2 バンプ）
9. **compiler 情報記録**（package_version / schema_version / git_commit）
10. **content_digest（内容再現性）と invocation_provenance（実行履歴）の分離**
11. **不変ディレクトリ出力**: builds/<content_digest>/ 方式・公開済み bundle 不変・latest ポインタのみ更新

**P1（生成器能力モデル）**
12. **generator_variant** 追加（musicgen melody 等 / Suno の通常・remix・cover・reference-audio 経路区別。model_version / interface / profile_version）
13. **capability（チャネル存在）と grip（実効性）の分離維持** — 入力可能を制御可能の根拠にしない

**P1（安全性恒久化 — 07-14 S1 の政策提案が承認された形）**
14. **AGENTS.md に「Persistent Artifact Safety Gate」チェックリスト追加**（単一 read で parse+hash / path 脱出検査 / build→dump→validate 読み戻しテスト / duplicate ID 拒否 / unknown 推測補完禁止 / 全構築後公開 / 公開途中失敗の注入テスト / input+output hash 記録 / checkout vs installed の資源差テスト / schema_version 未知値拒否）
