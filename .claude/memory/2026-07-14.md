### Design Decisions

- **sidecar-first の貫徹**: 全 6 PR で canonical `CompositionScore` を無変更（AR1-1 の ArrangementSpec も AR2-1 の IdentityManifest も非 canonical 入力/サイドカー。planning D1 準拠）。`PreservationSpec.identity_anchors` は additive optional で後方互換を CLI byte 不変まで pin
- **4 軸分離の実装着地**: fixity（採譜確定）/ preservation（編曲可否: hard・elastic・free）/ capability（入力チャネル存在: supported・experimental・unsupported・unknown）/ adherence（将来 AR4）を別モデル・別ファイルに分離。hard は「resolver における変更禁止」であって生成器保証でないことを docstring 契約化
- **推測補完禁止の一貫適用**: policy 省略の非 required anchor は contract に含めない（省略=free と解釈しない）/ profile に無いチャネルは unknown（supported にも unsupported にも倒さない）/ 変形語彙は planning 記載 7 種限定・語彙なきドメイン（lyrics/rhythm/motif）は elastic 不可（契約の空洞化拒否）/ hash は呼び出し側の明示注入のみ
- **決定論の作法**: 成果物にタイムスタンプ・絶対パス・output_dir を埋め込まない。AR1-3 の expected/ は実 CLI × リポジトリルート相対パスで生成し、2 回生成 sha256 一致を確認してからコミット（fresh-process スポット検証規律の適用）
- **Codex 指摘から結晶した頻出修正型（→ Handoff の政策提案）**: ①**path 封じ込め** — identity artifact（#178）と evidence（#180）で同型の「絶対パス拒否 + resolve() 後 is_relative_to」修正。#180 R3 で「字面（lexical）遡上判定は base 不要」（PurePosixPath 深さカウンタ）という切り分けの訂正を受けた ②**JSON 読み戻し経路の invariant safety net** — builder が保証する不変条件（mode/allow 整合・domain 語彙・anchor_id 一意）を schema validator でも強制（#179 ×2）③**多ファイル書き込みの原子性** — staging + os.replace + snapshot/rollback、残余窓=二重障害のみと honesty 明記（#176 ×2）④**packaged 配布整合** — package-data 追加 + evidence 実在検証を明示 evidence_base 限定化（既定 cwd の暗黙依存廃止。#180 ×2）⑤**hash とパースの同一バイト列**（TOCTOU、#176。以降の新 loader では設計段階で先取り済み）
- **exit code 規約の確定**: `svprpe arrange` の入力系エラーは stderr 1 行 + exit 1 統一（exit 2 は CLI 引数不正専用の既存慣習を温存）。compile 段の except は `OSError` 全体（#176 R4）
- **Scope 拡張の設計裁定 1 件**: pyproject.toml は memo で Scope OUT だったが、package-data 1 エントリ追加（依存追加でなく packaging 整合）に限って設計側で承認（#180）
