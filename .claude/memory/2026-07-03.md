  予定のまま」方向。最重要は R3 のブロッカー失効（K2=#117 完了済みが未反映）と

- **構造ギャップ 3 つ**（キュー外）: (1) 生成自動化＝人手律速の解体 (2) 第二生成器
  ＝「AI 音楽の MIDI」の一般性（単機種校正は標準でない）(3) 外部再現性・外部ユーザー。
  (1)(2) を一石二鳥で解く **MusicGen（transformers 経路・audiocraft 非依存）** を採用。

  Literal に既存、K0 fixture は手作りで実測ゼロ）→ PR 分割を A（runbook 器）/
  B（実バッチ→fixture+device profile）/ C（R3 ハーネス）に再編。
- **R3 計器の設計判定**: grip_map 既定は**空マッピング**（None だと K1=決定論シンセの
  校正が暗黙ロードされ確率的生成器の不一致を knob_dead に誤分類 — Sonnet 実装が
  brief の誤りを捕捉した好例）。rejection sampling は既定 `R3_SELECTION_FIELDS=
  (key, brightness)` にスコープ（bpm は R2 closeout 除外・補助センサーに選択を
  支配させない、Codex P2 起点）。score_ref は診断に使った CLI スコアで固定し
  manifest 不一致は stderr advisory（#128 の本文不変規律を踏襲）。

  のみ CI 決定論・CI は torch なしで全 pass（`musicgen` extra が torch 境界を運ぶ）。
- **G4 ゲート**: weights（facebook/musicgen-small、期待 CC-BY-NC-4.0）は VERIFY

### Design Decisions

- **bpm loose 記録の規律**: MusicGen K2 で bpm d=0.21 loose だが、正体は抽出器
  halving（start_bpm=180 で 7/8 が 172.27 回復）。device profile には素朴センサー
  基準の loose + halving quirk advisory で記録（R2 closeout「faster-side 回復は
  post-hoc 緩和」踏襲）。証拠系は最終的に 3 経路（素朴 0.21 / 高 prior 7/8 /
  CLAP d=2.60 重なりゼロ）で完結
- **profile scope の 2 軸 pin**: device profile の実測スコープを
  (model_id, revision) = musicgen-small @ 4c8334b0… に限定、runbook 側
  `profile_scope_advisory` が逸脱を stderr 通知（Codex P2×2 ラウンド）
- **R3 バッチの再生成判断**: profile 導入でコンパイル序列が変わり committed
  manifest が現経路と乖離 → opt-out でなく再生成を採用。n=5 の揺れ
  （key 2/5→0/5）は n=20 で 0.15 に確定、「選抜は存在するものからしか拾えない」
  限界と「選択=制御には per-field 保存率に見合う n が必要」を定量化
- **K3-2b は known_dead 宣言 2 行入り 5 ノブ R=8 で設計**: MIR 数値レンジ文字列 =
  語彙外という K3-1b 型宣言。ノイズ天井 |d|=0.848 が初実測され、異種チャネル間
  結合の天井超えゼロ = K3-2a の strong 群を over-reading から救済
- **センサーは階層でなく相補**（CLAP②）: 病理のある欄（bpm）は学習版が解像、
  クリーンな欄（brightness）は物理センサー優位
- **負債の裁定**: 高リスク 6 件は全て機械修正可能と判定し 3 部作で即日解消。
  key 一致判定 3 実装統一 / CLAP サイドカー化 / CI nightly extra は Design Memo
  要としてスコープ外（queue 化）
