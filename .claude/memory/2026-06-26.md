### Design Decisions
- **rock 生成スペック**: 初版プロンプトが物理層に浅いと user 指摘 → roundtrip 実験ログ
  （J-rock/J-ebm/Celtic）の規約に合わせ、BPM 数値・key・構造セクション・Avoid 句を明示し
  た 5 本（classic/hard/indie/blues/punk）に再構成。BPM・key・明暗を意図的に散らした。
- **分離軸の発見**: `spectral_bands.brilliance` 単独で 3 ジャンルが**重なりゼロの 3 バンド**
  に分離（orchestral ≤0.0954 | rock 0.139–0.196 | EDM ≥0.2119）。旧単一閾値 0.1537 が
  rock クラスタ中央を貫き classic/hard/blues→bass-music、indie/punk→orchestral に裂いて
  いた（audit で実証）。gap 中点 0.117/0.204 の 2 線へ置換し中域を rock に割当。
- **fix-up 採用**: 重なりゼロ・回帰ゼロで十分小さいため Design Memo→Codex でなく Claude
  が今セッションで config+audit+test+docs まで実装（user 選択）。
- **honesty**: rock は full sha256 + prompt 本文を manifest 記録（orchestral/EDM の
  prefix-only/PENDING 積み残しを rock では作らない）。bands 欠落時 fallback は rock/EDM の
  high_ratio が重なるため 2 値据え置き＝rock 判定は bands 必須と明記。
- **Codex P2 対応**: brilliance 境界の strict `_gt`/`_lt` がちょうど 0.117/0.204 で穴
  （general 落ち、4 桁丸めで実在し得る）→ 下限を `_min`(>=) 化し doc の半開区間 [0.117,
  0.204) と一致させ境界テスト追加。
- **R2-2 BPM 調査＝コードを意図的に触らない判断**: punk 175→123 halving の原因は
  `load_audio` 22050 リサンプル × start_bpm=120 prior（native 48k は 181 回復）。
  「閾値低下」「sr 上げ」いずれも大域的回帰を実データで確定: ① 内部 ratio は punk=1.057 <
  BPM 正検出 rock_03_indie=1.098 で autocorrelation-ratio では分離不能、② octave 調整後
  総誤差は 22050=12.9(最小)/44100=17.5/native=17.5 で native は punk を直す代わり
  synth_05(真値170) を 84.7 に半化して壊す。→ 単一ノブ修正は入れず、診断を docs に保全。
