### Design Decisions
- **PR #79（P3 fix-up）**:
  - `TODO(transcribe):` センチネル（定数 5 + ヘルパ 5 重複）を依存ゼロの leaf
    `svp_rpe/sentinels.py`（`TODO_SENTINEL_PREFIX` / `is_todo_sentinel`）へ集約。
    `compose → semantic_ci` の既存循環を踏まないよう **compose 配下でなくトップレベル**配置。
  - R1 corpus の C-gen brightness を `qualitative_cue → numeric_knob` 再分類（C-gen は
    compose 出力 = prompt_renderer が brightness を数値ノブ送出, case study §3）。bright→neutral
    の非保存が比較表から脱落していたのを復活。`send_form` 運用規約も docs 明文化。
- **PR #80（R2-2a 半折り検出）**:
  - 検出は onset-strength 自己相関の「×2 subdivision lag vs primary lag」比。**overlap 数
    `(n-lag)` で正規化**（Codex P2②: 生の `librosa.autocorrelate` は非正規化和で短尺クリップが
    上方バイアス→誤検出）。threshold 1.15、**×2 方向のみ**（÷2 は自己相関振幅から復元不能）。
  - `compute_bpm` のシグネチャ・契約は不変（beat 規則性の純測定）。曖昧性は直交軸として
    extractor で合成し `bpm_octave_ambiguous` / `bpm_candidates` を `PhysicalRPE` に追加。
  - **trust 配線（Codex P2①）**: cap 0.5 は `_is_untrusted_confidence`(<=0.0) に効かず inert
    だったため、`score_draft._bpm_untrusted()` で `bpm_octave_ambiguous` を sensor-blind 扱いに
    配線→曖昧 BPM は `TODO_BPM_UNDETECTED`(unlocked) 転記。flag が trust を担い cap は記録信号。
  - 二段レビュー: Sonnet が 6 件（dead guard / tuple 不変性 / extractor cap 未テスト等）、
    Codex が 2 件の実質 P2（trust 配線・正規化）を補完的に検出。両方妥当→全反映。
- **R2-1 調査（コード変更なし）**: 推定器は **明瞭に速い合成信号を halving しない**
  （アクセント付き 150/160/170/175 すべて正答）。halving するのは純インパルス列＝
  本質的にオクターブ曖昧な信号のみ（180→89.10 だが 89/90 も妥当な解釈でバグでない）。
  → Suno 175→89 の真病理（明瞭に速いトラックの誤読）は合成で再現不能、**R2-1 は R1-audio
  必須**を仮定でなく実証で確定。併せて当初疑った「検出器ギャップ」は誤認と訂正：検出器は
  設計ケース（subdivision 支配的）では発火するが、そのケースを推定器が halving する形で
  合成できないため、**実効力は Suno 問題音源が無いと検証不能**（これも R1-audio 待ち）。

### Handoff
- **R1-audio が単一クリティカルパス**: R2-1（アトラクタ再現確認）/ CV-scale 実校正 /
  ÷2 方向検出 / R2-2a 検出器の実効力検証 — **すべて R1-audio（人間が Suno 問題ケース音源を
  保存付き確保）待ち**。合成での代替は調査で否定済み（再試行しないこと）。
- **R2-2a は ×2 方向のみ shipped・実効力未検証**。real Suno 音源が入ったら manifest に
  calibratable レコード追加 →（a）推定器が実際に halving するか、（b）検出器が flag するかを
  記録するのが R2-1 の本体。
