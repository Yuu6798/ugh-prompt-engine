## 1. 要旨

- **到達率 5/6 系列・Pareto 改善ペア 5 件・全 16 測定周回で著者ツール使用 0**。
  L0b の操舵証拠（改善 1 件 = 最小実証）は、複数課題・複数著者個体で
  **改善 5 件へ頑健化**した。うち 1 系列（br_d3_s2）は key → structure の
  **2 軸を報告のみ根拠に逐次修理する 4 周回系列**で、閉ループ操舵の
  最長実証となった。
- **到達を分けたのは課題難度でなく著者の戦略選択だった**。最難と登録した
  BR-D3（複合相互作用）が 2/2 到達、既実証機構つきの BR-D1 が 1/2。
  唯一の未到達系列（br_d1_s1）は、著者が chorus 差異化に drone 系トークン
  （no kick / sub bass / low density）を使い、契約 v1 未開示の
  ヒント非加算・優先順位規則に 5 周回嵌り続けたもの =
  **failure_mode: contract_defect**（l0b record §4.1 と同型。
  L0a v2 反映後の再測対象）。
- **新規の契約欠陥 2 件を複数系列で再現実測**（v2 材料 §4）:
  自作ダイアトニック進行が調推定を平行調/属調へ倒す（3 系列で再現）、
  低→高エネルギー遷移側にのみ過渡帯（bridge）が観測される立ち上がり非対称
  （2 系列で再現・断片算術で機構分解）。
- R4 語句制約（drone 系 4 語の禁止）は難化要素として登録したが、実測では
  **罠語彙を封じて到達を助けた可能性**がある（保護効果仮説・§3.1）。

### 3.1 難易度軸の読み（登録時仮説との突合）

- 登録時の想定順（D1 易 → D3 難）は**反転**した。BR-D1 の既実証機構
  （drone トグル）は「機構が存在する」ことと「別個体が再発見できる」ことの
  乖離を露呈: s1 著者は機構の**素材**（drone 語彙）には到達したが、
  非加算規則を知らないため**組成**（全境界の統一トグル）に到達できなかった。
- R4 禁止下の 4 系列が全て到達した事実は、「drone 語彙は罠でもある
  （full energy と併記すると优先照合で意図と逆に働く）」ことの間接証拠。
  禁止が探索空間から罠を除去した**保護効果仮説**として記録する
  （n=6 の観察であり因果の実証ではない — 検証には D1 で R4 を付けた
  対照セルが要る）。

## 4. 新規に実測された契約 v1 の未開示特性（L0a v2 材料）

1. **自作 chord_progression は調推定を倒しうる**（3 系列 round1 で再現:
   F major ×2・C major ×1）。ダイアトニック内の進行はトニックを固定せず、
   検出器は progression 実体（C の 2 回出現 → C major 等）に従う。契約 §1 は
   「省略時はキーに応じた既定進行」とだけ言い、**自作進行が physical.key
   宣言より優勢に観測を決める**ことを開示していない。修理経路は 2 種が実測:
   (a) C#（和声的短音階の導音）を含む和音の導入（2 著者が独立到達）、
   (b) events 省略による既定進行回帰。→ v2 提案: 進行と調推定の関係開示 +
   「調を確実に観測させたい場合は省略が安全」の明記。
2. **立ち上がり非対称の過渡帯**（2 系列で再現）: 低→高エネルギー遷移
   （sparse/rest → full energy）の直後に幅約 5 秒の過渡帯が生じ bridge と
   観測される。高→低（full → release/drone）側は綺麗に検出される。
   br_d3_s2 r4 の断片算術（bridge 実長 5.25s ≈ intro 宣言残余 2.41s +
   chorus1 立ち上がり 2.83s）が機構を定量分解し、intro を観測実長へ
   短縮する修理で解消を実証。→ v2 提案: 可行窓開示（現状 3 分割中間長のみ）
   への立ち上がり過渡の追記。
3. **ヒント非加算・優先順位規則の再確認**（br_d1_s1 の 5 周回）: 既知
   （l0b record §4.1）だが、本バッテリーで「観測境界の完全同値ペア
   （r1=r2・r3=r4）」という決定論ならではの強い evidence を追加。
   "release" と "full energy" が同水準へ写像される等価性も未開示のまま
   著者判断を歪めた（br_d2_s1 r1 の outro）。

## 5. D 原則遵守・off-contract 会計

- **D2**: 著者 = 毎周回別個体の Sonnet（Agent ツール model="sonnet" 明示・
  解決先ファミリー claude-sonnet-5）。ツール使用実測 = **全 16 測定周回で
  0 回**。可視ペイロードは compose_payload.py 出力のみ + 凍結ラッパ
  （機械連結）。
- **off-contract イベント 1 件**（台帳 off_contract_events）: br_d1_s2
  round1 の初回試行で coordinator のプロンプト転写に 1 箇所の文字化けが
  混入（契約 §0 の 1 語）。送信直後に自己検出し、著者を**応答生成前に停止・
  破棄**（汚染応答は存在しない）→ 正規手順（同一ターン内ファイル読取→直写）
  で再実行。当該試行はどの周回にも算入していない。
- **転写忠実性の限界開示**: 著者への送信バイト列を事後検証する手段は
  ハーネス上存在しない（Agent spawn はプロンプト文字列を受けるのみ）。
  本バッテリーは (a) composer 出力の sha256 pin、(b) 同一ターン内
  読取→直写の固定手順、(c) ヘッダのみ差分の場合の機械 diff / md5 検証、
  で転写リスクを縮小したが、送信時点の byte 同一性の機械証明は未達 —
  **後続実験ではファイル参照で著者へ渡せる機構（ハーネス側）が本質的解**。
- **D5/D6**: 全周回・全軸 band=measured。Pareto 述語は frozen/pareto.yaml
  無変更（総合スコア禁止維持）。

## 6. 限界と残課題

- **n の限界**: 2 系列/課題・5 周上限の第 1 バッテリー。到達率の差
  （BR-D1 1/2 vs 他 2/2）は著者サンプリング揺らぎと分離できていない。
  保護効果仮説（§3.1）の検証には R4 有無の対照セルが要る。
- **contract_defect の再測**: br_d1_s1 は登録どおり「L0a v2 反映後に
  同一課題で再測」対象（v2 にヒント解決規則が開示されれば到達するか）。
- **複数モデル比較**（D2 差し替え実証）は User 方針決裁どおり未着手のまま
  後続へ。
- 課題設計は凍結判定器（section map 2 種・key/brightness 定数）の枠内に
  制約された。判定器拡張なしで作れる難易度セルはほぼ使い切っており、
  次のバッテリーは判定器側の拡張（別 map の pin 追加等）とセットになる。
