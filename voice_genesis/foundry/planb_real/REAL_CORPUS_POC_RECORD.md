## 4. 読み取り

### 4-1. 事前登録 TRF 主軸は「終端 /ri/」でだけ立つ

R0（baseline）の `nasal_gain_db`:

| probe 種 | R0 値 [dB] | failure_present（≥1.0） |
|---|---|---|
| terminal /ri/ | **+5.708 / +5.618** | **yes / yes** |
| terminal /i/ | +1.162 / +2.608 | yes（弱い）/ yes |
| terminal /N/ | +0.289 / −0.301 | **no / no** |
| medial /ri/ | +0.499 / −1.365 | **no / no** |

**語中 /ri/ では立たず、終端 /N/ でも立たず、終端 /ri/ でだけ大きく立つ。**
これは「り→ん」が終端固有の現象だという記述と整合する、独立に得られた実測。
surrogate PoC では合成故障を自分で入れて軸の弁別力を確かめたが、
ここでは**故障を入れていない実素材**で同じ軸が probe 依存に応答している。

### 4-2. 改善は R4 でのみ起きる（プラン §5 Case C 型）

terminal /ri/ の主軸推移:

```
pair 1:  R0 +5.708 → R1 +5.774 → R2 +5.599 → R3 +5.668 → R4 +1.562
pair 2:  R0 +5.618 → R1 +5.515 → R2 +5.882 → R3 +6.078 → R4 +2.064
```

**F0 だけ・duration だけ・その両方では動かない。dynamics + release を入れた
R4 で初めて -4.15/-3.55 dB 動く。** `drift_db` も 7.6→2.5 / 7.3→2.8 と同時に下がる。
プラン §5 の分類では Case A（duration）でも Case B（F0）でもなく、
**Case C = terminal release は複合 Performance Skill** に対応する。

surrogate では release の「母音コア保持」単独で全治したが、実データでは
R4 まで行かないと動かない。**surrogate で得た帰属はそのままでは実素材に転移しない。**

### 4-3. G7 が拾った 2 件の FAIL は別々の理由

| ペア | 理由 |
|---|---|
| `terminal_ri` 2018#215 | 主軸は必要量を満たした（+1.684 ≤ +4.201）が、**副軸 `energy_tail_db` が -0.48 → +7.09（+7.56 dB）** で回帰許容を超えた。= 終端が減衰せず持続する方向へ悪化した（連続発声側）。PJS の release taper を、native の減衰がもっと速い Ritsu ノートへ載せた結果 |
| `terminal_i` 1st_color#86 | R0 が +1.162 と failure_present しきい（1.0）の**すぐ上**。必要改善量 1.0 dB に対し 0.29 dB しか下がらず不通過。境界事例であり「破綻がほぼ無い probe に改善を要求した」形 |

どちらも**ゲートが設計どおり働いた**結果であり、事後に閾値を緩めていない。

### 4-4. surrogate で見つけた主軸の利得交絡が、実データで再現した

`medial_ri` 1st_color#357 の R4 だけが異常値を出した:

```
nasal_gain_db  -1.365 → +7.230   （+8.6 dB の跳ね）
nasal_gain_shape_db  -2.127 → -2.547   （ほぼ不変）
identity LSD        3.17 → 8.53   /  identity shape LSD  3.18 → 3.39
```

**レベル正規化するとどちらも動かない。**つまりこの跳ねはテクスチャの変化ではなく
energy 移植による**利得の変化**であり、surrogate PoC が「生の `nasal_gain_db` は
利得に交絡する」と実測した欠陥が、実コーパスで独立に再現したことになる。

instruction §11 が求める「real corpus での独立 validation」のうち、
**gain robustness の 1 点は本走行で満たされた**（/i/・/u/ の単調性と陽性/陰性対照は未実施）。
§0-8/§11 の規律に従い、**主軸は差し替えていない**。`nasal_gain_shape_db` は
`CANDIDATE_SECONDARY_AXIS` のまま併記した。

| 段 | 想定外に動いた軸 | 原因 |
|---|---|---|
| R2（duration のみ） | `f0_dev_rmse_cents` | unit 尺を変えるとフレーム窓が変わり、目標 dev 系列の再サンプルが変わる（**測定上の交絡**） |
| R1（F0 のみ） | `energy_corr` | F0 を変えると再解析のスペクトル包絡推定が変わる（**測定上の交絡**） |
| R1（terminal /N/） | 動くべき `f0_dev_rmse` が動かない | PJS 側の当該 probe に移植すべき逸脱がほぼ無い |

いずれも「介入が漏れている」のではなく「軸が直交していない」。
**ゲート定義は結果を見て緩めていない。** FAIL として記録し、次版の課題として残す。

### 4-6. §6 の share 転写が構造的に no-op になる場合

`terminal_N` の 2 ペアは R2 の `note_split_mae_ms` の変化が **0.00**。
撥音 /N/ は先行子音を持たないノートなので、子音/母音 share の転写が
定義上何もしない（`lo == hi`）。これは実装不具合ではなく §6 の性質であり、
`timing_transplant_is_noop` として record に出している。
**「timing skill を交換した」と読んではならない probe がある**という申し送り。

### 4-7. Identity は保たれている（機械代理）

全 8 ペア × 全 5 段で `donor_LSD − identity_LSD` は +1.1〜+20.8 dB（最小値でも正）。
出力は常に PJS より Ritsu に近い。G4（donor テクスチャへの単調接近）も
全ペアで不成立 = PJS の声へ寄っただけではない。ただし**これは機械代理**であり、
プラン §10 G-ear（聴感）は未実施。

## 6. 走行の履歴（正直会計）

本記録の数値は**第 4 回目の走行**のもの。第 1〜3 回は計器・実装・材料の欠陥を出して捨てた。

| 走行 | 出来事 |
|---|---|
| 1 | ゲートは動いたが `f0_sag_cents` が ±1000cent 超を返した。**F0 再解析の倍/半周期誤検出**と、抽出側（コア中央値基準）と計測側（unit 全体中央値基準）の**参照点不一致**を発見 |
| 2 | 上記 2 点を修正（再解析の探索域を合成 F0 の実レンジへ制限 / 参照点をコアへ統一）。すると **語中 probe に terminal release が当たっていた**ことが露見（medial の R4 で identity 距離 3.0→8.9、終端エネルギー +19.7dB）。原因は「probe だから terminal」と決め打ちしていたこと。加えて PJS 側 f0 の倍周期誤検出を **clamp（上限で止める）で「意図的な跳ね」として移植**していた |
| 3 | terminal フラグを lab の実フレーズ末判定に変更、f0 逸脱は clamp ではなく**外れ値除外**に変更 |
| 4 | **User の耳判定が成立しなかった**（「サンプルが 1 秒しかないから両方とも判定できない」）。probe の前文脈が 2 音素しか無く、出力が 1 秒程度にしかなっていなかった。文脈を 22 音素へ広げて全ペアを再レンダ（terminal /ri/ で 3.6 秒 = 「ぽたり ぽたり」と 2 回鳴る）。**本記録の数値**。計測は probe unit だけを見るので測る対象は変わらず、判定も走行 3 と同一（主軸 R0 は +5.601/+6.178 → +5.708/+5.618 と 0.1〜0.6 dB 動いたが、PASS/FAIL/NOT_EVALUABLE の内訳は 8 ペアとも不変） |

いずれも「ゲートを通すため」ではなく「測っているものが違った」ための修正であり、
**事前登録した主軸・判定ルール・閾値の導出手順は 4 回とも変えていない**。
