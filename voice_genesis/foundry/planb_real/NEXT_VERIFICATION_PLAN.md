## 0. このタスクの問いは何か

instruction §18 が中心仮説を定義している:

> Voice ≠ indivisible speaker representation
> Voice / Singer = Identity + Performance Skills
> として少なくとも部分的に分解・再結合可能かを実コーパスで確認する

§0 の成功主張の上限も
「**部分的に分離された実歌唱形質を、Identity とは別経路で交換可能**」までである。

**terminal /ri/ の修理は本タスクの目的ではない**（§18 が明示: 「この実験の最終目的は
terminal /ri/ を修理することだけではない」）。terminal /ri/ は §8 で
**probe の場所**として指定されているのであって、直すべき対象として指定されているのではない。

### スコープ外（VoiceGenesis / run 8 へ渡す）

| 項目 | 扱い |
|---|---|
| り→ん破綻そのものの解決 | **VoiceGenesis の未解決**。本タスクは触れない |
| run 7 checkpoint の出力取得・測定 | run 8 の資産。本タスクへ持ち込まない |
| TRF 軸の再登録 | run 8 側の判断。本タスクからは**所見を渡すのみ** |

### run 8 へ渡す所見（本タスクの副産物）

事前登録の TRF 主軸 `nasal_gain_db` を **Ritsu 原音**（合成を通していない収録音）へ
当てると terminal /ri/ で **+5.654 / +5.853 dB** を示す（R0 とほぼ同値）。
つまりこの軸は「モデルの破綻」ではなく「人間の歌唱に元からある終端の性質」を読む。
`failure_present = 絶対値 >= 1.0 dB` という門は**自然な人間の歌唱を「破綻あり」と
判定する**。run 8 で TRF 軸を登録する際は、絶対値ではなく
**基準（人間の歌唱）からの逸脱**として定義することを勧める。

生データ = [`results/anchor_reference_check.json`](results/anchor_reference_check.json)

## 1. 本タスクで詰める箇所（優先順）

### P0 — 「交換できたか」を問える形にする

| # | 項目 | 何が問題か | 詰め方 | 何が外れるか |
|---|---|---|---|---|
| **P0-1** | **`R0n`（Ritsu 自身の Performance）をラダーへ追加** | 現行 R0 は F0 をユニット中央値へ**平坦化**しており、Ritsu 自身の歌い方を捨てている。つまり R0 は「neutral baseline」ではなく「**Performance 除去**」。この土台では「Ritsu の Performance を PJS の Performance へ**交換**できたか」を問えない（比較相手が無い） | R0n = identity + **Ritsu 自身の f0 / 尺 / 強弱**（= 純粋な再合成）を常設対照にする。R0（平坦）は下限、R0n は native、R1–R4 は PJS 成分 | **中心仮説そのもの**。交換の成否が native 比で言えるようになる |
| **P0-2** | **介入範囲を note → phrase へ** | Performance を probe ノート 1 個にしか当てていない（3.6 秒・約 11 音節中の最後 1 音節）。耳は「歌い方を全く移植できてない」と判定した。**成分は届いている**（probe ノートの F0 標準偏差 2.07→22.43Hz）が、1 音節では「歌い方」として知覚されない | `--intervention-scope {note,phrase}` を追加。note = G3 の帰属用（軸を汚さない）、phrase = G-ear 用（知覚が成立する）と用途で分ける | 「交換できた」の知覚的裏付け |
| **P0-3** | **交換の成否を測る軸を定義する** | 現行の performance 軸（f0_dev_rmse / note_split_mae / energy_corr / taper_rmse）は「**PJS の目標へどれだけ近いか**」しか測らない。「Ritsu 自身から**どれだけ離れたか**」を測っていないので、**交換が起きたのか単に壊れたのかを区別できない** | 各軸を `native(R0n)` と `target(PJS)` の 2 基準で測り、(離れた, 近づいた) の 2 次元で報告する | 交換の定義そのもの |

### P1 — S3（2 要素以上の独立交換）へ進む

| # | 項目 | 何が問題か | 詰め方 |
|---|---|---|---|
| **P1-1** | **G3 の軸交絡を切り分ける** | R2（尺のみ）で f0 軸が、R1（F0 のみ）で energy 軸が動く。**介入の漏れか測定の交絡か未確認**。S3 の唯一のブロッカー | 合成器の内部値（意図）と再解析値（結果）を両方測り、どちらの段で交絡が生じるか特定。測定窓を rung 間で固定する案を次走行で事前登録 |
| **P1-2** | **§6 の share 転写が構造的に no-op になる場合** | 撥音 /N/ など先行子音の無いノートでは定義上何も動かない（実測 2 ペア）。比率が同じペアでも同様。**timing 成分が評価できない probe がある** | ペア選定で `timing_transplant_is_noop` を除外条件にするか、転写単位を「ノート内配分」から「フレーズ内のノート長配分」へ拡張するかの設計判断 |
| **P1-3** | **release / dynamics の表現を疑う** | 耳が R4 を「音量の上がり方が不自然」と評した。副軸 `energy_tail_db` は −1.13 → **+6.96 dB**。PJS の taper を native の減衰がもっと速い Ritsu ノートへ絶対量で載せている | taper を絶対 dB ではなく **native の減衰形に対する相対**として転写する案を検討。ここは Performance 側の表現の問題であって identity の問題ではない |

### P2 — 判定材料の質（Identity 側）

| # | 項目 | 何が問題か | 詰め方 |
|---|---|---|---|
| **P2-1** | **原音忠実度**（Identity の同一性とは**別軸**） | 耳は「R 系はみな同じ歌い手」（Q1=yes）と判定した一方、「原音として通るか」は no。`ap×0.25` で明確に改善したが往復単体でも通らない | 非周期性以外の残差機序を特定（位相・包絡の平滑化・フレーム周期）。**S2/S3 のブロッカーではない**が、雑音が判定対象を覆うと G-ear が成立しない（実測: 項目6 が判定不能になった） |
| **P2-2** | **雑音軸が無い** | 耳が「ノイズ」を検出したが WORLD の `ap` は逆向き（ANCHOR 0.540 > R0 0.507） | 原音相対の帯域別 SNR / 倍音対雑音比を候補に、耳判定と相関する軸を探す。**相関が取れるまで軸を名乗らせない** |
| **P2-3** | **`AP_SCALE=0.25` は単一 probe の耳判定に基づく暫定値** | 息成分は identity の一部。全素材へ一律に掛けている。効果は高音区間（f0≈498Hz）に集中し、低めの probe ではほぼ不変だった | 複数 probe・複数区間で再判定。素材依存が確認済みなので **f0 に応じた適応**も候補 |

### P3 — 標本と手続き

| # | 項目 | 何が問題か | 詰め方 |
|---|---|---|---|
| **P3-1** | **耳の標本が薄い** | 判定者 1 名・1 セッション・盲検 2 回・**機械値を先に開示してしまった** | 判定を先に取り機械値は後で開示する手順に固定。ペア数を増やす |
| **P3-2** | **PJS 側 probe の薄さ** | terminal /ri/ が 4 件、terminal /su/ は 0 件（唯一の 1 件が不整合ファイル） | §12 S4（複数曲・held-out）の律速。probe 語彙を広げるか Performance ドナーを追加するか |
| **P3-3** | **TRF ゲートの門が誤って発火する** | `failure_present = 絶対値 >= 1.0 dB` は人間の自然な歌唱でも成立する（実測）。**本タスクは破綻を直す立場ではない**ので、門が誤発火すると「直せなかった」と誤読される | 門を**基準からの逸脱**へ改める（次走行の事前登録として）。目的は「破綻を直す」ことではなく「破綻が無い素材では NOT_EVALUABLE と正しく言う」こと |

## 2. 依存関係

```
P0-1（R0n 追加）
   ├─→ P0-3（交換の成否を測る軸: native からの距離 × target への距離）
   └─→ P0-2（介入範囲を phrase へ）── 知覚での裏付け
                                          └─→ P3-1（耳の標本）

P1-1（G3 交絡の切り分け）──→ S3
P1-2（timing no-op）──────→ S3（timing 成分が測れる probe を確保）
P1-3（release 表現）──────→ 耳の「不自然」の解消

P2-1/P2-2（忠実度・雑音軸）── 独立。G-ear が成立する材料の質を上げる
```

**最初に着手すべきは P0-1。** 現行の R0 は「Ritsu の Performance を除去した状態」で
あって「Ritsu の Performance」ではない。交換の相手が居ないまま
「交換できたか」を測っていたことになる。ここを直すと、
§18 の中心仮説（Identity と Performance の分解・**再結合**）が初めて実験の形になる。
