## 0. 一行結論

**分離機構は実装でき、決定論・テクスチャ非混入・成分帰属のすべてが機械ゲートを
通った。ただし本走行が示したのは「機構の十分性」までであり、リツの声の維持
（受入 1 の聴感）と実 DiffSinger の り→ん改善（受入 2）は実資産と耳が無く未達
のまま残っている。** 副産物として、事前登録した TRF 主軸に 2 つの実測欠陥
（利得交絡・母音依存）が見つかり、代替軸の候補が 1 本立った。

## 4. 読み取り

### 4-1. プラン §5 の Case 判定 = **release 支配**（ただし合成故障に対して）

陽性対照の主軸（`nasal_gain_shape_db`、R0 = +4.446 dB）に対する各成分単独の効果:

| 成分 | 単独での主軸 | Δ vs R0 | 判定 |
|---|---|---|---|
| F0（R1） | +4.446 | **±0.000** | 効果なし |
| duration（R2） | +4.037 | −0.409 | 微小（故障窓が unit 長の比率で入るため） |
| energy（S1） | +4.443 | −0.003 | **効果なし** |
| release, taper のみ（S4） | +4.350 | −0.096 | **効果なし** |
| release, コア保持あり（S2） | **+0.011** | **−4.435** | **単独で全治** |

プラン §5 の分類では Case A（duration）でも Case B（F0）でもなく、**release
skill の中の「母音コア保持」1 成分**に帰属した。R4（全成分）の +0.028 は S2 と
実質同値で、他成分は主軸に何も足していない。

**この帰属は合成故障に対するものである。** 故障を「終端で母音包絡が鼻音へ流れる」
と定義した以上、それを直すのは「流れないよう包絡を保持する」操作であり、
そこに循環がある。本走行が示すのは *機構の十分性*（コア保持だけで、テクスチャを
一切借りずに、この型の終端破綻を消せる）であって、実 DiffSinger の破綻が
同じ型だという主張ではない。

### 4-2. 陰性対照が「改善を捏造しない」

故障なしでは R0 の主軸 = −1.840 dB < 1.0 dB で `failure_present=False` となり、
G7 は **`not_evaluable`** を返した。全 9 段を通して主軸は −1.87〜−1.55 dB の
狭帯に留まり、どの成分を入れても「改善」が立たない。これは
「ラダーを回せば何か良くなったように見える」という失敗様式に対する対照になる。

### 4-3. 事前登録した主軸の 2 つの欠陥（本走行最大の副産物）

**(a) 利得交絡**: S4（taper のみ・コア保持なし）は鼻音ドリフトを一切直していない
のに、生の `nasal_gain_db` は 2.718 → 0.562 と「改善」した。release 窓の平均包絡が
レベル加重平均なので、終端を減衰させるだけで変質フレームの寄与が小さくなる。
レベル正規化版 `nasal_gain_shape_db` では 4.446 → 4.350（ほぼ不変）と正しく出る。

**(b) 母音依存**: 用量反応掃引で、生の `nasal_gain_db` は終端 `/ri/` では単調
（range +4.93 dB）だが、終端 `/su/` では**非単調・range −0.17 dB = ほぼ盲**。
`/u/` の包絡がもともと鼻音包絡に近く、軸のヘッドルームが無い。
`nasal_gain_shape_db` は `/ri/` +4.95 dB・`/su/` +5.72 dB でどちらも単調。

**(c) `drift_db` は非単調**: 終端レベルの変化に交絡し、depth 0 → 0.2 で一度下がる。
形状版 `drift_shape_db` は `/ri/` では単調だが `/su/` では非単調。

→ **run 8 の TRF 軸登録への推奨**: 主軸には**レベル正規化した鼻音方向距離**
（`nasal_gain_shape_db` 相当）を採り、生のレベル加重版と `drift_db` は診断軸に
留めること。事前登録の規律上、本走行の判定は凍結どおり生の軸で行い、
**遡って差し替えていない**（差し替えるなら次走行の登録として）。

### 4-4. identity 側は動いていない

全 9 段で identity コア距離 2.85–3.05 dB・donor 距離 6.99–7.24 dB、margin は
+3.97〜+4.37 dB で安定した。identity 距離の下限 ~2.9 dB は
「合成 → 再解析」の往復床であり、R0 の時点で既にこの値である
（= ラダーは identity 距離を悪化させていない）。

出力は常に donor より identity に 4 dB 近い。プラン §7.1 が禁じた
「PJS の声を混ぜただけ」ではないことの、構造（G2/G3）に加えた**実測側の証拠**。

### 4-5. 成分の分離は成立している

- duration: dur MAE 143.46 ms → **0.97 ms**（R2 以降）
- F0: f0_dev RMSE 60.57 → **31.67 cent**（R3）
- energy: 相関 0.849 → **0.919**（R4 / S1）
- release: taper RMSE 8.65 → **3.96 dB**（S4）/ 4.23 dB（S2）

各成分が自分の軸だけを期待方向へ動かしており（G5 pass）、
プラン §7.2「別々に交換し、どれが効いたか保持する」を満たす。

フレーズ中間 unit（`ぎ@23`）の drift は R0 0.577 → R4 1.346（+0.769 dB、
許容 1.0 以内）で、その増分は **F0 移植由来**（R1 単独で 1.220）。
release skill 単独（S2）では 0.577 と完全不変 = 終端以外を触っていない。

## 6. 実資産走行への引き渡し

コードは代替と実資産で分岐しない。追加で要るのは 2 つだけ:

1. **wav**: リツ VCV バンクを F1.4 レンダラで鳴らした出力（Identity 側）と
   PJS 実歌唱（Performance 側）
2. **Unit 境界**: PJS の lab / リツの oto.ini から
   `pb_tracks.units_from_boundaries(labels, boundaries_s, terminal_flags=...)` へ

実資産走行では `--no-fault` で走らせる（合成故障は入れない）。R0 に実 TRF が
あれば `failure_present=True` になって G7 が実測ゲートとして機能し、
無ければ `not_evaluable` が返る — それは「この発話に破綻が無い」という実測結果。

## 7. 申し送り（未解決）

1. **probe 語彙が足りない**。実資産走行の前に `/i/`・`/N/`・phrase-medial `/ri/`
   を含む短い probe スコアを 1 本用意すること
2. **合成故障は 1 モデルのみ**。実 TRF が別機序（laryngeal / voicing の崩れ等）
   なら本陽性対照はその機序を代表しない。プラン §5 Case E の射程は本ハーネス外
3. **`energy` 移植は置換実装**（identity 自身の unit 内エンベロープを reference の
   形へ差し替える）。加算だと二重計上で発散する（初回実測でピーク 322.9 まで
