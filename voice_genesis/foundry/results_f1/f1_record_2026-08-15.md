## 1. 実装決定

### 1.1 単位切り出し（donor_bank.py）

- vocadito clip 2 は notes アノテーション CSV（`Annotations/Notes/vocadito_2_notesA1.csv`,
  A2 も存在）が **存在した**。主経路（notes CSV）を採用し、フォールバック
  （エネルギー谷再帰分割）は発動しなかった。annotator は **A1** を採用
  （A1/A2 の選択基準は設計書に無く、実装決定。record §5 に記録）。
- CSV 形式（vocadito README 準拠）: 列 = start_sec, pitch_hz, duration_sec、
  ヘッダ無し。76 ノート、duration 分布は 0.0058s〜1.533s（中央値 0.264s）。
- **実装決定（設計書に無い下限）**: 15ms 未満（`MIN_UNIT_FRAMES_ABS=3` フレーム
  @5ms）になる CSV ノートは単位として採用しない（アノテーション上のグリッチに
  近いと判断）。実測: 76 ノート中 **2 件が drop**（`n_dropped_short=2`）、
  74 単位を採用。クリップ発動（donor 範囲外）は 0 件。
- フォールバック（`units_from_energy_valleys`）は単体テストのみで経路確認済み
  （実 vocadito では未発動）。

### 1.2 単位選択（units.py）

- コスト重み初期値は設計書 §5 Risks の指示どおり `w_p=1.0, w_d=0.3, w_c=1.0`
  のまま使用（耳判定調整は本 record の範囲外）。
- 候補半音レンジの段階拡張ステップ = 3 半音、安全弁 36 半音（3 オクターブ、
  実装決定）。**4 曲 × 2 voice の全 32 note 選択で拡張は 0 回**
  （sakura/umi ともに `selection_stats.n_expansions=0`）。donor の音域が
  score の音域を十分カバーしていたことを意味する。
- 接合コスト用の 24 log 帯域ベクトルの距離は L2（ユークリッド）ノルムを採用
  （設計書に距離関数の指定なし、実装決定）。

### 1.3 伸縮キャップとループ（units.resolve_unit_to_note）

- 比率 [0.5, 2.0] キャップは設計書どおり。**実測が示す重要な事実**: donor
  単位の中央値長（0.264s）が score のノート長（sakura: 1拍0.833s/2拍1.667s/
  4拍3.333s、umi: 1拍0.682s/2拍1.364s/3拍2.045s）より大幅に短いため、
  **往復ループ（`extended_looped`）が主経路になった**:
  - sakura: 20 note 中 17 件が `extended_looped`、3 件が `none`（無キャップ）、
    `compressed_truncated` は 0 件
  - umi: 12 note 中 6 件が `extended_looped`、6 件が `none`、
    `compressed_truncated` は 0 件
  - 圧縮切り詰め（比率 <0.5）は sakura/umi とも 0 件（発生せず）
- **実装決定（設計書に明記の無い edge case）**: 比率 <0.5（過圧縮）の場合は
  キャップ後（比率0.5）の結果を先頭から target 長へ切り詰め、万一それでも
  不足すれば末尾フレームを保持して埋める。今回のデータでは未発動。

### 1.4 接合クロスフェード（joins.py）

- 30ms（6 フレーム @5ms）を境界直前フレームに適用し、直前 unit の実フレームを
  直後 unit の先頭フレームへ向けてブレンドする方式（境界そのものは無改変 =
  直後 unit の最初のフレームと連続）。**実装簡略化（設計書に具体アルゴリズム
  指定なし）**: true overlap-add ではなく単側ブレンド。総フレーム数は timeline
  由来のまま変化しない。
- フレーズ内連続 note のみ対象（`has_join_to_prev = not is_phrase_first`）。
  実測: sakura 14 件 / umi 9 件のジョインを適用、スキップ（対象 unit が
  crossfade 幅未満）は 0 件。
- フレーズ間ブレスは carry-forward（直前有効フレーム保持）で埋めた:
  sakura `n_gap_frames=250`、umi `n_gap_frames=100`。

### 1.5 Performance 遺伝子 v0（perf_genes.py）

- singer/performance.py の note track（vibrato_depth_cents=0 でベース取得・
  ポルタメント 55ms 込み）に onset_glide / vibrato（ノート毎位相リセット）/
  drift / jitter を加算合成（cents 空間）してから乗算で f0 に反映。
- drift・jitter は glottal.py の `[UNDERSPEC-S1-4]` 教訓を踏襲し、cumsum
  ランダムウォークではなく**ブロック単位の i.i.d. 乱数 + 線形補間**方式を採用
  （drift はブロック長 = 1/(2*rate_hz) 秒 ≈ 1.25s @0.4Hz、jitter は 10ms 固定）。
- seed は `spec.seed`（drift）/ `spec.seed+1`（jitter）で分離（glottal.py の
  seed+1/seed+2 慣習を踏襲）。

### 機序判読（記録者）

1. **日本語発声になっていないのは構造的必然だった**: ドナー vocadito clip 2 は
   **スペイン語歌唱**（metadata 実確認）。v0 の unit 選択は音素次元を持たない
   （設計書 §4 で意図的にスコープ外）ため、出力はスペイン語音節の断片の再配列になる。
   vocadito 全 40 クリップ に日本語は存在しない（英 17・仏 9・タガログ 6・北京語 2 ほか）
2. **試験設計の誤り（記録者の責）**: 耳のゲートには階層がある —
   「声か」（F1c で通過）→「**その言語の発声か**」（未着手）→「自然さの精度」。
   下位ゲート未通過のまま上位（接合品質・作り分け）を質問したため判定不能になった。
   S6–S9 の教訓「知覚手がかりの階層を耳が一段ずつ暴露する」の再演であり、
   音素同一性は精度ではなく**ゲート**である
3. こもった開始 5 秒: 開幕の長音ノート群（ループ発動 17/20）に暗い unit が選ばれ
   往復ループで固定された可能性が高い。ただし音素ゲート未通過下では診断優先度低
4. 判定不能も判定である: 「このサンプル群では判断困難」を有効な耳判定として記録し、
   F1 v0 の接合品質・作り分けの評価は**未実施**（≠ 失敗）として扱う

### 帰結 — 次ゲート = 音素同一性（F1.1）

- 好都合な事実: スペイン語は日本語と同じ **5 母音体系**（a/e/i/o/u ≈ あえいおう）。

### 8.1 F1.1-A 母音クラス選択（vowel_class.py + units.py 拡張）

**F1/F2 推定・分類**: 各 donor unit の中央 50% フレームの median log-sp から
F1(200-1200Hz帯ピーク)/F2(700-3000Hz帯・F2>F1+150Hz制約) を推定し、5 母音
プロトタイプへの log-Hz 距離で分類（margin<0.05 で低信頼 "x"）。

**実ドナーでの分布（vocadito clip 2, A1 notes, 74 units）**:

| a | e | i | o | u | x |
|---|---|---|---|---|---|
| 14 | 1 | 6 | 28 | 18 | 7 |

**較正 1 回（記録・設計書追補 F1.1-A item2 の許容範囲内）**: 設計書指定の
"e" プロトタイプ (500,2100) では 5 クラス中 "e" が非空にならなかった
（実測: a=14 e=0 i=6 o=28 u=18 x=8。donor の実測 F1/F2 散布に、a クラスタ
（F2≈1200-1700Hz）と i クラスタ（F2≈2350-2850Hz）の間に構造的な空隙があり、
原型 (500,2100) 近傍には 1 unit も存在しなかった）。実測 a クラスタ重心
log 空間 (876.6Hz, 1412.7Hz) と i クラスタ重心 log 空間 (329.4Hz, 2576.4Hz)
の log-空間中点 (537.4Hz, 1907.8Hz) を新しい "e" 原型として採用し（丸め値
537.0/1908.0）、境界上で低信頼 "x" だった unit12 (F1=609.4Hz, F2=1570.3Hz)
が margin 0.104 で "e" に確定分類され、5 クラス非空を満たした。
`vowel_class.py` の `VOWEL_PROTOTYPES["e"]` docstring にこの経緯を記録済み。

**選択への母音制約（units.py `select_units` 拡張）**: 候補コストに母音不一致
ペナルティ `w_v` を加算（一致=0 / 近縁母音 a↔o, i↔e, u↔o=半ペナルティ / それ
以外="x"含め満額）。目標母音は `mora_to_vowel_target()`（score の
`mora.vowel` から導出、撥音「ん」は子音層委譲のため無制約 = None）。

**実装決定（要 record）— w_v の較正**: 設計書指定の既定値 `w_v=10.0` を
実ドナーで検証したところ、既存の接合コスト `cost_concat`（24 log 帯域 L2
距離、w_c=1.0）が異なる母音の unit 間で ~15-22 の値を取る（母音間で sp
包絡が構造的に大きく異なるため）ことが判明し、`w_v=10.0` のままでは音域内に
候補が実在するのに母音制約が無視される事例が複数発生した（w_v=10.0 実測:
sakura 14/20 exact + 3/20 near_fallback + **3/20 mismatch**、umi 10/12 exact
+ 1/12 fallback + **1/12 mismatch**）。`w_v` を段階的に引き上げて実測した
ところ 18.0 で不一致 0 件に達したため、安全域込みで **`DEFAULT_W_V=25.0`**
を採用した（`units.py` に経緯と実測値を docstring 記録）。

さらに、目標母音の unit が現在の半音候補レンジ内に 1 つも（近縁含め）無い

### 8.2 F1.1-B 子音オンセット移植（consonants.py）

**WORLD 領域への翻訳方針**: singer/ 側はフォルマント極フィルタ（目標
F1..F4 + voicing 混合比）で子音を表現するが、WORLD の sp は既にフレーム
ごとの周波数包絡そのもの。「voicing 低下」は sp 振幅スケール、
「ap→1（noise_gain）」は文字通り ap を 1 に寄せる（WORLD は ap=1 のフレームを
非周期励振として合成するため sp 帯域整形だけで band-noise が実現できる）、
「フォルマント目標」は sp への対数周波数ガウス型 bump/notch ゲインとして
移植した。

**実装した子音種と出典（sakura/umi 歌詞に現れる onset の和集合 = s,k,t,g,r,
n,m,h,y,w）**:

| 種別 | onset | 主な移植数値 | 一次出典 |
|---|---|---|---|
| 破裂/摩擦 | s,k,t,g | duration 70/55/50/35ms、帯域中心 6000/2500/5000/1800Hz | `singer/render_song.py` `_CONSONANT_TIMING_MS` / `_NOISE_BAND_SPEC` / `_band_noise`（帯域マスク関数形） |
| 弾き音 | r | duration 28ms、振幅ディップ 0.15、F3 減衰率 0.40(=1-0.60) | `singer/render_song.py` `_CONSONANT_TIMING_MS["r"]`、`singer/render_song_v2.py` `R_FLAP_VOICING_V2`/`R_FLAP_F3_RATIO_V2` |
| 鼻音 murmur→locus | n,m | murmur duration 100ms・F1≈250Hz・notch中心1150Hz/幅0.6oct/深さ0.80・HF cutoff 3000Hz/-18dB・振幅0.15、locus hold 16ms・F1=300Hz・F2(n=1700/m=1000Hz)、遷移 murmur→locus 8ms・locus→vowel 22ms | `singer/formant_tv.py` `NASAL_FORMANTS_HZ`、`singer/render_song_v3.py` `NASAL_NOTCH_*`/`NASAL_HF_*`/`NASAL_DIP_VOICING_V3`、`singer/render_song_v5.py`（S9 実測）`LOCUS_HOLD_MS`/`LOCUS_F1_HZ`/`PLACE_LOCUS_F2_HZ`/`*_TRANSITION_MS` |
| 気息 | h | duration 55ms | `singer/render_song.py` `_CONSONANT_TIMING_MS["h"]`（帯域整形は追補指示どおり「後続母音の包絡」を保持する設計に変更、[実装決定・出典なし] 節参照） |
| グライド | y,w | duration 70ms、遷移元 i/u プロトタイプ | `singer/render_song.py` `_CONSONANT_TIMING_MS`/`_GLIDE_TARGETS`、`vowel_class.VOWEL_PROTOTYPES`（i/u）を共通化して再利用 |

`consonants.py` の各定数に出典行コメントを付記済み。gain_db 系の一部
パラメータ（F1/F2 bump の強調量など）は一次ソースに数値が無いため
`[実装決定・出典なし]` と明記した。

**単体テスト**: `tests/test_adapter_consonants.py`（25 件）で子種別ごとの
形状（murmur の低域集中・burst の帯域別高域比較・locus の n/m F2 差・
glide の window 内収束）・決定論再現・onset=None/未知子音の no-op を検証。

**render.py 配線**: `--no-consonants` CLI フラグで無効化可能（A/B 用）。

### 8.5 Open Questions（F1.1）

1. **"e" プロトタイプの較正**: §8.1 の較正（(500,2100)→(537.0,1908.0)）は
   単一ドナー・単一クリップの実測分布に基づく 1 回限りの較正。他クリップ/
   他ドナーでも同じ空隙構造が再現するかは未検証。
2. **`DEFAULT_W_V` の較正（10.0→25.0）**: 設計書の既定値のままでは実ドナーの
   concat cost スケール（~15-22）に負けて母音制約が機能しない事例が生じたため
   引き上げた。この値も本ドナー・本 2 曲での実測に基づく較正であり、語彙が
   広がった場合（"e" を含む歌詞等）は再検証が必要。
3. **/r/ の F3 近似**: WORLD sp は極を明示的に持たないため、singer/ 側の
   「F3 を 0.60 倍」という調音位置レシピを「固定 nominal 中心 2700Hz・幅
   0.5oct の帯域減衰」として近似した（`consonants.py` `R_F3_NOMINAL_HZ`）。
   母音ごとに実際の F3 は異なるはずだが、本実装では母音非依存の固定値を使う。
4. **/h/ のレシピ差し替え**: 追補 F1.1-B は /h/ を「後続母音の包絡で整形した
   気息ノイズ」と明示的に指定しており、これは `render_song.py` の実際の
   /h/ 実装（`fricative_broad` 帯域ノイズ、/s/ と同型）とは異なる。追補の
   指示を優先し、sp 形状を変えず ap のみ引き上げる実装とした（`H_AP_LIFT`/
   `H_AMP_SCALE` に一次ソースなし・[実装決定]）。
5. **母音空集合時のピッチレンジ拡張**: §8.1 で追加した「母音候補が音域内に
   無ければ既存の段階拡張機構を流用する」拡張は設計書に明記されていない
   実装決定。既存の「候補が空なら拡張」ロジックの自然な一般化と判断したが、
   設計意図と異なる可能性がある。
6. **耳判定素材**: 本節で生成した 5 WAV は耳判定待ち（未実施）。判定質問は
   設計書どおり「日本語の発声・歌詞に聞こえるか」。§6b の言語ゲート通過を
   意図した実装だが、実際に聞こえるかは未検証。
