## 2. 実装決定

### 2.1 UTAU oto.ini パーサ（donor_bank_utau.py）

- **文字コード**: Shift-JIS（cp932）想定、UTF-8 デコード失敗時のみフォール
  バック（実測: 波音リツの oto.ini は cp932）。
- **右ブランク（cutoff）の解釈較正**: 実データの大多数（A3: 1235/1237,
  F4: 1236/1237 行）は符号なし（正号）で書かれているが、これを「ファイル
  先頭からの絶対位置」として解釈すると offset > cutoff の矛盾行が複数発生
  する。`wav_duration_ms - abs(blank_ms)`（符号に関わらず「ファイル終端
  からの距離」として扱う）で全行が一貫して正の長さを持つことを実測で確認し、
  この解釈を採用した（`donor_bank_utau.cutoff_position_ms` docstring 参照。
  単体テストで数値検算済み）。
- **母音安定区間 / 子音区間の分割**: 各エイリアスの consonant フィールド
  終端（`offset+consonant`）を境に、それ以前を子音オンセット素材
  （`ConsonantClip`）、それ以降 cutoff までを母音核 unit として分割
  （設計書 F1.2-B のとおり）。
- **音高解決**: 音源フォルダ名（A3, F4）を科学的音高表記として解釈し
  Hz へ変換（`note_name_to_hz`。A4=440Hz 規約。A3=220.0Hz, F4=349.23Hz）。
  各 unit の `median_f0` は実際に WORLD で分析した f0 トラックの中央値を
  優先し、無声区間のみの場合はフォルダのピッチにフォールバックする。
- **かな正規化**: `singer/phoneme_jp.kana_to_morae`（sakura/umi 専用の
  縮小テーブル）をまず試み、未対応文字（濁音の一部・半濁音・小書き母音等）
  は独自の `_EXTRA_TABLE` で補う。sakura/umi の onset 集合
  `{s,k,t,g,r,n,m,h,y,w}` 以外（b,p,z,d,ゔ 等）は選択には使われないが
  bank 統計には含める。促音「っ」は専用ステータス `sokuon` で unit 化から
  除外（記録のみ）。
- **計算資源境界**: 波音リツ強連続音は pitch フォルダあたり実 wav 約 228
  個（VCV 連続音のため 1 wav に平均 5-6 エイリアスが同居）。全 wav の
  WORLD 分析は 10 分規模になり実行予算を圧迫するため、`_select_wav_subset`
  による貪欲被覆選択（必須子音オンセットを先に充足 → 母音ごと
  `min_units_per_vowel=8` 件を満たすまで追加 → `max_wav_files=40` で
  打ち切り）で各ピッチフォルダ 22 wav（計 44 wav）のみ分析した
  （帯域指標での最適化ではなく計算資源スコープの決定。実測 100.2 秒）。

### 2.2 PJS .lab パーサ（donor_bank_lab.py）

- **時刻単位**: HTS 標準の 100ns 単位（`start/end * 1e-7` = 秒）。
- **mora グルーピング**: 音素区間列を走査し、子音（複数連続することは
  想定音素セットでは基本発生しない）をバッファへ積み、母音（a/i/u/e/o）
  到達時に 1 mora として確定。撥音「N」は独立 mora（onset=None,
  vowel="N"）。無音（pau/xx）は境界として子音バッファをリセット（無音を
  跨いだ子音の母音結合を防止）。促音の閉鎖「cl」は直後の実子音バッファへ
  吸収し、onset ラベルには使わない（開始時刻のみ引き継ぐ）。
- **[実装決定・設計書に無い判断]** F1.2-C 本文は「mora 単位（子音+母音核）
  を unit 化」とだけ記すが、Part 3 (F1.2-D) は両ドナー共通の「recorded
  子音前置」ロジックを要求している。UTAU バンク（F1.2-B）と対称に、PJS
  も「母音核 unit + 子音クリップ別保持」の分割方式を採用した
  （`donor_bank_utau.ConsonantClip` をそのまま再利用）。これにより
  render.py の子音前置ロジックを 2 ドナーで完全共用できる。
- **移調（オクターブ単位）**: donor（男声）の生 median_f0（有声 unit の
  中央値）と、render 呼び出し側が渡す `target_median_hz`（score の
  ノート中央値 Hz）の比を最寄りのオクターブ（12 半音の倍数）へ丸めて
  `median_f0` に適用する（`compute_octave_transpose`）。**この移調は
  選択コスト用の `median_f0` にのみ作用し、実際の合成 f0 は F1 設計凍結
  どおり perf_genes が生成するため出力ピッチには影響しない**（joins.py
  の「f0 はドナー由来を使わない」約定と整合）。
- **計算資源境界**: PJS 全 100 曲（音声合計 27.2 分）は実行予算を圧迫する
  ため、`_select_lab_files` による貪欲被覆選択（必須子音オンセット + 5
  母音を充足する最小ファイル集合、`min_files=6, max_files=10`）で
  **pjs001–pjs006, pjs008 の計 7 ファイルのみ**分析した（実測 46.7 秒）。

### 2.3 配線（render.py, F1.2-D）

- `--donor {vocadito,ritsu,pjs}`（既定 `vocadito`）、
  `--consonant-source {recorded,synthetic,none}`（既定は donor に応じて
  自動解決: vocadito → `synthetic`、ritsu/pjs → `recorded`）、
  `--voicebank-root`（ritsu の UTAU ルート / pjs のコーパスルート）を追加。
  `--wav`/`--notes-csv` は vocadito 専用（オプション化、donor=vocadito 時
  のみ実行時バリデーションで必須化）。
- **既存 CLI 挙動は不変**: `donor` 省略時は従来どおり `--wav`/`--notes-csv`
  必須・`consonant_source="synthetic"`（F1.1-B のまま）。回帰確認として
  vocadito sakura neutral を再実行し、vowel_distribution
  `{a:14,e:1,i:6,o:28,u:18,x:7}` が `vowel_class.py` の較正コメント記載値
  と一致することを確認済み（§4 参照）。
- **録音済み子音前置**（`render.prepend_recorded_consonant`、純関数として
  分離しテスト可能化）: `consonant_source="recorded"` かつ該当 onset の
  クリップが bank に存在する場合、クリップ（自然長・非伸縮）を母音核
  frame 列の先頭へ連結する。総 frame 数はクリップ分だけ増加し、以降の
  note の配置カーソルもその分後ろへずれる（**[実装決定・設計書に無い
  edge case]** 元の performance タイムラインとの厳密な尺整合は本段階の
  非目標とし、伸長分は許容する。f0 は `total_samples` でクランプされる
  ため末尾フレームは直前 f0 を保持する近似になるが、sakura/umi の実測では
  無視できる規模）。クリップが無ければ synthetic（F1.1-B）へフォール
  バックし件数を記録する（今回の 4 レンダーで **フォールバック発生 0 件**、
  §4 参照）。クリップ選択は bank 側で「句頭（`- X`）エイリアス優先 → 
  wav名/alias名昇順」に決定論ソート済みのものを先頭固定選択。

## 7. identity 留意

- **波音リツは既知の UTAU キャラクター声**である。規約上はクレジット不要・
  加工後再配布可だが、識別可能な既存キャラクターの声を用いる以上、
  `voice_spec.py` の `warp`（freq_warp / spectral_tilt / breath_lift）は
  **Genome 変形の最低量適用対象**として扱うべきことを明記する
  （本 record では `presets/neutral.json` をそのまま使用しており、
  リツ固有の変形プリセットは未作成 = Open Questions §8 参照）。
- PJS は研究コーパスの合成音声（特定個人の識別を主目的としない話者）で
  あり、同種の identity 留意は不要と判断した。
