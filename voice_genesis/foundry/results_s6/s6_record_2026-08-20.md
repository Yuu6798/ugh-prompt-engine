### 5-1. Q12 = **部分裁定**（局所改善は観測・事前登録の articulation 測度は `undetermined`）

**訂正の履歴（2 段階）**:

1. 初版は「達成」+「**実録音教師は合成教師の代替として機能する**」と書いた。
   → 後段を**撤回**（代替性の主張には反復走行が要る）
2. 第 1 訂正は「**articulation 側に限り達成**」とした。→ **これも撤回**する。
   下に挙げる実測はいずれも**語尾（終端）の局所所見**であって、
   DESIGN_S6 §1.2 が事前登録した articulation 測度（ritsu/pjs/user の
   **さ行 onset 明瞭性**）は §5-1b のとおり**判定されていない**。
   終端の所見を onset の代理として使うと、**Q12 の未判定の半分を
   陽性の結論に化けさせる**ことになる

本節は run 9 以降の設計根拠として参照されるため、射程を実測に合わせる。

**観測された局所所見（これ自体は確か）**:

- ritsu の「みわたす」語尾「す」は run 7 で**改善**（run 6 は「維持」）
- pjs は**改善のみ**（副作用なし）
- この範囲で、合成教師（d3synth）を外しても①の破綻矯正は失われなかった

**裁定**:

| 対象 | 裁定 |
|---|---|
| 語尾「す」の局所退行（事前登録 1/2） | **改善**（観測） |
| **さ行 onset 明瞭性 = articulation 測度（事前登録 2/2）** | **`undetermined`**（未判定・§5-1b） |
| sustain / 終端解放の保存 | **非改善**（下記 2） |
| 「実録音教師は合成教師の代替として機能する」 | **撤回** |

**したがって「articulation が保存された」とは書かない。** 言えるのは
「**事前登録した局所退行 2 点のうち『す』は改善した**」までである。

**言えない範囲（初版の超過分）**:

1. **「代替として機能する」は言い過ぎ**。正確には
   「**run 7 で ritsu の語尾「す」と pjs に改善が観測された**」までである。
   ~~「articulation 側の矯正を失わせなかった」~~ という言い換えも**使わない** —
   観測されたのは**終端**の所見だけで、事前登録の articulation 測度
   （さ行 onset）は未判定だからである（本節冒頭の訂正 2 と同じ理由。
   訂正した直後に同じ語で言い換えると撤回が空文になる）。
   さらに代替性の主張には同一契約の反復走行が要る（s5_record §6.2 が
   「この帰属の確定には同一契約の反復走行（未実施）が要る」と既に明記している
   規律の、本節への対称適用）
2. **sustain 側は 1 つも動いていない**。り→ん は run5→7 一貫して未解決（§5-2）・

### 5-2. り→ん破綻 = **教師交代の影響下にない継続課題**

**当初この記録は「り→ん破綻は run 7 の副作用」と書きかけたが、撤回した。**
③の三世代判定で「run5 から 7 で根本解決にならず」が確認され、
**d3synth を投入していた run 5 / run 6 の時点で既に未解決**だったことが
判明したため。

この撤回には設計上の含意がある。`singer/score_d3_sustain.py` の docstring は
当該素材を「**長母音サステインの崩壊（り→ん破綻）対策の主力データ**」と
位置づけ、d3synth 40 セル（4 score × 10 seed）のうち 10 セルを占めていた。
しかし User 判定は run 5 時点でも破綻が残っていたことを示す。すなわち
**`DESIGN_S3_backfill` の対策は「投入した」だけで「効いた」ことが検証されない
まま対策済みとして扱われていた**。

**帰属の限定（正直会計）**: 上記は「d3_sustain が無効だった」ことまでは
示さない。示せるのは「**d3_sustain を投入した run 5 でも り→ん破綻は
User の聴取で残っていた**」までである。投入しなかった場合にもっと悪化して
いた可能性は排除できない（対照が無い）。

### 5-3. り→ん破綻は**話者依存**

**破綻を起こさないのは pjs 系のみ**。ritsu は run5〜7 を通じて破綻し、
user も「みわたす」語尾で連続発声を起こす。話者をまたいで一様でない以上、
共有デコーダ側の一般的欠陥だけでは説明できず、**話者データ側の特性**が
効いている可能性が高い。ここは次段の実測課題とする（本記録では未判定）。

### 5-4. さくら / うみ の非対称

全話者で**うみは成立・さくらで破綻が出る**。さくらは 2 拍・4 拍の長い音符を
持ち、うみは短い。**持続音長との相関**が疑われるが、曲は 2 曲しかなく
交絡要因（音域・音素構成・フレーズ数）を分離できていないため**未判定**。

### 5-5. あみたろ単体のさくら破綻について

あみたろは**教師話者であって Identity 頂点ではない**（DESIGN_DONOR_EXPANSION
§0 裁定）。その単体レンダの破綻は「教師が歌えない」ことを示すに過ぎず、
**教師としての適格性を否定しない**。教師の役割は音素明瞭性の供給であり、
実際 5-1 のとおり他話者の①改善は達成されている。

## 6. 設計への申し送り

1. **教師交代の等価性は dosage だけでは足りない**。DESIGN_S6 は投入時間を
