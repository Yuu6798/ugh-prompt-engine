## 0. 裁定（User 採用 2026-08-18）

ドナー募集の定義を「歌手」から「**AI 学習に明示同意した声の提供者**」へ拡張する。
根拠は 2 つの実測: (1) リツ D2 = 非歌唱の連続音素材でも S1 耳ゲートを通過
（歌唱能力は共有デコーダが担い、ドナーは声色を供出すればよい）、(2) run 4 で
user 宅録（非プロ歌唱）が第三の声の方向性陽性に到達。

第 1 期の採用候補と役割:

| 候補 | 役割 | 根拠（User 耳判定 + 調査） |
|---|---|---|
| **つくよみちゃんコーパス** | **第 4 Identity 頂点候補** | 声色が既存 3 頂点の空間を最も広げる配置（User 試聴裁定）。AI 学習・商用許可の調査確度は「部分確認」= intake 前提 §3-1 の充足が先 |
| **あみたろ（ITA コーパス）** | **発音教師枠（補完素材）** | レア音素（シュバイツァー等）の明瞭発音を User が試聴確認。AI 学習明示許可・商用可・収録スペック公開（暗騒音 18.5dB・T60 220ms）で調査確度「確認済み」 |

## 1. 役割語彙の一般化（Identity 頂点 / 教師）

run 5 の d3synth で導入した**教師/ドナー分離**（spk_id は与えるが Identity
単体には入れない）を一般語彙として凍結する:

- **Identity 頂点**: 実録音・来歴清潔（明示許諾）・単体（simplex）の頂点として
  補間に参加する声。「誰でもない声」の証明力はここの来歴清潔性に依存する
- **教師**: 共有デコーダの学習に寄与するが Identity 空間に入らない話者。
  **合成教師**（d3synth = render 生成物・品質天井あり）と**実録音教師**
  （あみたろ = render アーティファクト無し・品質天井制約なし）の 2 種を区別する
- 教師にも spk_id を与える（末尾追加のみ・既存 ID 不変の規律は
  assemble の spk_id 固定規約を継承）

## 2. 採用候補の個別契約

### 2-1. つくよみちゃん（第 4 Identity 頂点候補）

intake 前提（**全充足まで学習投入不可**・順序どおり）:

1. **規約の逐語 pin**: survey で「部分確認」の箇所（AI 学習可否の逐語原文・
   クレジット免除条件）を一次ページから取得し、取得日時 + 規約本文 sha256 を
   台帳化（user_donor_ledger と同思想の許諾証跡）
2. **ウィスパー f0 スクリーニング**: 高音ウィスパー系声質は f0 抽出が不安定に
   なりやすい仮説があるため、少量（コーパス 10 文程度）で f0 追跡可否・
   voicing 率を先に実測してから本 intake を判断する（fail した場合は
   頂点候補を撤回し調査の次点へ — 実測前に本裁定を確定扱いしない）
3. **クレジット組み込み方式の決定**: 必須クレジットを成果物（モデル・
   合成音の公開物）のどこに載せるかを intake 時に決めて記帳する

### 2-2. あみたろ（発音教師枠）

1. 規約は調査で確認済みだが、intake 時に**規約ページの逐語 pin**（sha256 +
   取得日時）を同様に台帳化する（Web 規約は変更されうるため取得時点を固定）
2. **50% ルールの会計**: 「あみたろ声が学習データの 50% 超を占めるモデルの
   単体販売不可」に対し、assemble 時のデータセット構成比（セグメント数・
   総時間）を manifest に記録し、比率が機械的に検証できる形にする
   （教師枠 = 少量投入の想定では構造的に安全圏だが、会計は残す）
3. クレジット要件（「学習データ: あみたろの声素材工房」形式）を成果物公開時の
   必須項目として記帳
4. 禁止用途（ディープフェイク・なりすまし等）は本プロジェクトの既存倫理線と
   整合 — 逸脱用途が生じないことを intake 記録に明記

## 3. run 順序（単一介入の継承）

- run 6 = user 正規化 + T3（既定・DESIGN_S4 §7）は不変
- **run 7 = 本トラックのどちらか 1 介入のみ**。先後は run 5 の Q7 判定で分岐:
  - **Q7 が D3 起因を示唆** → あみたろ教師交代を先行（D3 引退の受け皿。
    実録音教師で①の破綻矯正効果が保存されるかが run 7 の主検証点になる）
  - **Q7 が user 起因を示唆 / 判定不能** → つくよみ頂点追加を先行
    （教師系は現状維持で頂点拡張の検証に集中）
- いずれも既存規律を全継承: スクラッチ学習・pin 台帳・耳ゲート様式・
  予算 cap は各 run の Design Memo で個別凍結

## 4. VG-E0 への影響

- **頂点追加は voice-genome schema の改訂**（座標軸 3 → 4・niche グリッドの
  再定義）= VG-E0 §2/§3 の凍結仕様の版番上げを伴う正式改訂 PR が必要。
  run 7 でつくよみ頂点を入れる場合、VG-E1 の第 0 世代取り込みとの順序を
  その時点の Design Memo で裁定する
- **教師追加は schema 影響なし**（Identity 空間外のため VG-E0 に非接触）

## 5. 見送り・不適の記録（調査確定分）

- **SSS 系**（ずんだもん・四国めたん・きりたん）: 商用不可 or 有償ライセンスで
  商用パスと衝突 — 不適
- **COEIROINK**: 機械学習用データとしての使用を規約で明示禁止 — 不適
- **UTAU 音源界隈**: AI 学習の明示許可音源は調査で発見できず（禁止定型文が
  普及）— 既定不適。リツは例外的存在と確認
- **VOICEVOX 系出力**: 合成音声のため「実録音のみ品質源泉」原則で対象外
- **JVS corpus**: 保留（商用は要連絡・裏声/ささやき収録は音域被覆の観点で
  魅力あり。頂点大量追加が必要になった局面で再訪）
- **Common Voice**: ドナー不適（MP3 圧縮・群衆宅録品質）。将来の事前学習
  素材候補としてのみ記録
