# 第3ドナー積み立て収録キット（`recording_kit`）

現行 2 ドナー（D1=PJS, D2=波音リツ VCV）に対する User 自身の歌声を、
「気が向いた時に少しずつ」積み立てる形で収録するためのキット。

設計凍結事項（変更しない）:

- **1 ファイル = 1 カード**（20〜60 秒）
- **順不同**（好きなカードから録ってよい）
- **中断/録り直し自由**（1 カードだけ録って終わってもよい）
- **スマホ録音可**
- **形式不問**（wav/m4a/mp3 など。`intake.py` が正規化する）
- **優先度順**（カードは T0 → T3 の順で効果が高い。詳細は `cards.md`）

## 1. 目的

現行 2 ドナーは工場出荷ワークフロー用の素材で、それぞれ構造的な手薄
領域を持つ（詳細は `cards.md` 冒頭の「被覆分析サマリ」）。第3ドナー
（User 自身の歌声）は、この手薄領域を狙い撃ちで補う目的で少しずつ
積み立てる。全カードを一度に揃える必要はない。

## 2. 録り方（3行）

1. **静かめの部屋で**（無音区間の環境ノイズが少ないほど良い。完全な
   防音は不要）
2. **スマホ録音で可**（内蔵マイクで十分。ボイスメモアプリ等そのまま）
3. **1 カード = 1 ファイル**（`cards.md` の ID をファイル名先頭に入れる。
   例: `UC-003_あ_2026-08-20.m4a`）

## 3. 送り方

以下のいずれかで届ける:

- **このチャットに直接添付**
- **AI-Drive の `/user_donor/incoming/` に置く**

どちらでも構わない。録った順・カードの順不同で構わない。

## 4. どこまで録ればいいか

**全部録る必要はない。上から順に効く。**

`cards.md` は T0（最優先・アラインメント基準）→ T1（歌唱長母音・最重要
の手薄領域）→ T2（手薄音素の短フレーズ）→ T3（任意・音域端/強弱）の
優先度順に並んでいる。途中で止めても、上位カードほど単体で価値がある
ように設計してある。

## 5. カード一覧

優先度順の全カード（ID・所要秒数・狙い）は `cards.md` を参照。

## 6. 取り込み処理

送られた音声は `intake.py`（骨格・stub）が 24kHz mono wav へ正規化し、
`user_donor_ledger.json` にカード ID・sha256・受領日・長さ・ラウドネス
概況を追記する。アラインメント（音素境界付け）は今後の別タスク
（本 stub の TODO）。

```bash
python voice_genesis/foundry/recording_kit/intake.py \
    --incoming-dir  <受領ファイルを置いたディレクトリ> \
    --out-dir       <正規化後 wav の出力先> \
    --ledger        voice_genesis/foundry/recording_kit/user_donor_ledger.json
```

## 7. カードの狙いの根拠

`cards.md` 冒頭の被覆分析サマリは `voice_genesis/foundry/s1_dataprep/README.md`
（D1/D2 変換器の既知の制限・統合辞書の話者専用記号）と
`voice_genesis/foundry/results_s2/s2_record_2026-08-16.md` §11.4
（リツ方向 embed 全般に共通する長母音サステインの崩壊、いわゆる
「り→ん」現象と H3 仮説の裏付け）、`voice_genesis/foundry/jp_corpus_survey_2026-08-15.md`
（PJS = 単独男性歌手 100 曲、単声域）を根拠にしている。

## 8. 権利・会計注記

録音は User 自身の歌声であるため、**学習利用そのものは自由**（本人の
声を本人が使う）。ただし配合済みの合成声（他ドナーとの spk_embed
補間・摂動を経た声）に User の声質の痕跡がどの程度残るかは、
`voice_genesis/foundry/results_s2/genome_ledger.json` と同型の
「genome 台帳 + rights_class」会計で個別に管理する（本キット自体は
生素材の受領のみを扱い、配合後の権利会計は S2 ループ側の責務）。
他ドナー（PJS: CC BY-SA 4.0 / リツ: 権利者本人配布・利用規約準拠）との
混合物を公開・配布する場合は、混合元それぞれの継承条件を満たす必要が
ある点に変わりはない。
