## 1. 実装決定

### 1.1 VCV alias 実在調査（F1.4-A item1/3）

波音リツ強連続音 Ver1.5.1 の oto.ini（A3/F4 各 1237 行）を実測した。

- **「a か」形式（VCV・prev_vowel 付き）**: 各 pitch dir で 1059 行（非フレーズ
  先頭）。sakura/umi が実際に必要とする 27 個の文脈キー（後述 §2）は **A3/F4 の
  両方で 100%（27/27）過不足なく存在**し、重複エイリアスも無い（1 文脈=1 unit）。
- **「- か」形式（フレーズ先頭形）**: 各 pitch dir で 178 行存在。sakura/umi が
  必要とするフレーズ先頭 8 種（さ/や/そ/み/か/う/ひ/お）は全て存在。
- **「a R」等の休止形（フレーズ末用エイリアス）**: **実在しない**（A3/F4 とも
  1237 行中 0 件。alias 末尾トークンが `R`/`r`/`-`/`ー`/`息` になる行を全走査して
  確認）。波音リツ強連続音は「強連続音」（VCV 中心の連続音）バンクであり、
  CVVC 系や一部の単独音バンクに見られる明示的な語尾（ending）録音を持たない
  構成と判断する。
  **[実装決定・record 記録]** 設計書 F1.4-A item3「無ければ減衰テーパで代替」の
  対応として、新規コードは追加しなかった。`singer/performance.py`
  `build_amplitude_envelope` が既に「フレーズ末ノートの減衰（末尾 30% を
  1.0→0.55 へ線形フェード）」を実装しており（F1.3 で「振幅の唯一の権威」に
  確定済み）、これがそのまま代替の減衰テーパとして機能すると解釈した
  （§5 Open Questions #1 参照）。

### 1.2 donor_bank.py: `vowel_core_start_frame`（F1.4-A item1）

`DonorUnit` に `vowel_core_start_frame: Optional[int] = None` を追加した
（unit 先頭からの相対フレームオフセット。`[0, vowel_core_start_frame)` =
録音済み調音遷移＝伸縮しない固定区間、`[vowel_core_start_frame, end)` =
母音定常部＝伸縮/ループ対象）。`None`（vocadito/pjs/旧 UTAU unit）は後方互換で
unit 全体を母音定常部として扱う。

F1.3-B item1「母音核区間の平均パワー」という正規化基準の記述に VCV 化後も
忠実であるため、`_unit_mean_power`（→ `normalize_unit_energy`）を
`vowel_core_start_frame` 以降のみを使うよう変更した（`_unit_vowel_core_range`
新設）。**[実装決定・record 記録]** これにより、unit 先頭の調音遷移（前母音尾+
子音、収録レベルが母音核と異なりうる）が正規化基準を歪めることを防ぐ
（`test_normalize_unit_energy_does_not_distort_by_transition_level` で検算済み）。
ゲイン自体は unit 全体（`start_frame:end_frame`）へ一様に適用する
（単一の連続録音のため、母音核基準のゲインを遷移部にもそのまま使うのが自然
という F1.3 からの方針を継続）。

### 1.3 donor_bank_utau.py v2: VCV unit 化（F1.4-A item1/2）

`build_donor_bank_utau_vcv` を新設した。v1 `build_donor_bank_utau`（母音核のみ
切り出し + 別保持の `ConsonantClip`）は F1.3 までの互換テストのため関数として
残置するが、**render.py の `donor="ritsu"` 経路からはもう呼ばない**。

- unit の frame 範囲を `[offset, cutoff)`（従来の母音核のみ `[consonant_end,
  cutoff)` から拡張）へ変更。これにより録音済みの「前母音尾 + 子音 + 母音
  アタック」の遷移全体が unit 内に保持される（設計書「録音済み調音遷移を切らずに
  保持する」）。
- `vowel_core_start_frame = consonant_end_frame - offset_frame`（unit 内相対値）
  として遷移/母音核境界を記録する。
- `overlap_frames` / `preutterance_frames` は F1.3 と同じ計算式（oto の
  overlap_ms / preutterance_ms をフレーム化）だが、**基準点が unit 先頭
  （= offset）のまま**なので意味が変わらず、そのまま「unit 内オフセット」として
  再利用できる（実装変更不要だった点を記録）。
- 子音は unit に録り込まれるため `ConsonantClip` 別保持は行わない
  （F1.4-B item3「録音子音クリップ挿入経路も VCV 経路では廃止」）。戻り値は
  `(DonorBank, unit_contexts, stats)` の 3 要素（v1 の 4 要素 `consonant_clips`
  を廃止）。

### 1.4 wav 部分集合選択の文脈駆動化（F1.4-A、[実装決定・record 記録]）

v1 の `_select_wav_subset`（オンセット被覆 + 母音あたり最小件数のヒューリス
ティック）は、VCV 経路では「sakura/umi が実際に必要とする文脈キーを過不足なく
含む」ことを保証しない（計算資源境界の設計意図とは無関係な理由で mora が
解決不能になりうる）。そのため `_select_wav_subset_for_contexts` を新設し、
render.py から渡される `required_contexts`（レンダリング対象スコアが必要とする
`(prev_vowel, mora)` の重複無しリスト）を**過不足なく含む最小 wav ファイル集合**
をファイル名昇順の決定論走査で選ぶよう変更した。`required_contexts=None` の
場合は文脈非依存の汎用フォールバック（ファイル名昇順で `max_wav_files` 件）を
維持し、単体テスト・将来スコア向けの汎用性を保った。

実測（sakura×ritsu）: A3/F4 各 21 wav ファイル（sakura 単独）で 17 文脈が過不足
なく解決（`n_wav_files_analyzed=28`、後述 §2）。umi 単独では A3/F4 各 10 wav
ファイルで 11 文脈。WORLD 分析コストは「wav ファイル数」に比例するため
（unit 切り出し方式に依存しない）、F1.3 までの計算資源境界方針は維持される。

### 1.5 units.py: VCV 選択（F1.4-C）

`select_vcv_units` を新設した。候補フィルタは 3 段階:

1. **exact**: `unit_contexts[idx] == (target.prev_vowel, target.mora)` の完全一致
2. **near**（フォールバック）: mora のみ一致（prev_vowel を無視 = 「x 扱い」）
3. **global**（想定外の最終フォールバック）: mora すら一致する unit が皆無の場合、
   全 unit を候補にする

候補内のコストは `w_p*|Δsemitone| + w_d*|log(dur比)|` のみ（**[実装決定・record
記録]** 設計書 F1.4-C は「従来コストの音高項・長さ項は継続、母音ペナルティは
文脈キー一致で自動充足」と述べるのみで concat cost (`w_c`) の扱いには触れて
いない。文脈キー完全一致フィルタにより候補数が通常 1〜2（A3/F4 の 2 音階分）に
絞られるため、concat cost の実質的な弁別力がほぼ失われることと、設計書が
明示的に継続を指定したのが音高・長さ項のみであることから、VCV 選択では
concat cost を計算しない判断とした。§5 Open Questions #2 参照）。tie は
`unit.index` 昇順（決定論）。

### 1.6 units.py: VCV 尺合わせ（F1.4-A item1 / F1.4 §5）

`resolve_vcv_unit_to_note` を新設した。unit を「録音済み調音遷移（先頭
`vowel_core_start_frame` フレーム・**伸縮せずそのまま保持**）」+「母音定常部
（残り・F1.3 と同じ [0.5,2.0] キャップ + 往復ループの overlap-add 機構で目標残長
へ伸縮）」の 2 区間に分けて処理し、単純連結する（同一連続録音由来のため境界に
不連続は生じない）。目標長が調音遷移長を下回る縮退ケース（実コーパスでは
最短ノートでも遷移長よりずっと長いため未発動・後述 §4）は遷移を切り詰め
`head_clipped=True` で記録する設計とした。

### 1.7 render.py: preutterance 消費（F1.4-B item2/3）

`_build_vcv_placements` を新設した。**フレーズ先頭ノート**（`is_phrase_first`）
のみ、配置開始位置を `min(preutterance_frames, 直前のブレスギャップ frames)`
だけ cursor より前へずらす（ブレス 0.25s=50frame の範囲内で自動的にクリップ
される。§2 で実測: sakura 5/6 フレーズ頭で発動・全件無クリップ、umi 1/3
フレーズ頭で発動・無クリップ。umi の残り 2 件はブレスギャップが無い/使い切れ
ないケースではなく、全曲最初のフレーズ（ギャップ 0 のため shift=0 で自然に
不発動）と、必要な shift が実際に 0 未満にならないケースの記録漏れがない
ことを個別確認済み）。`end_frame` は shift の影響を受けない（次フレーズの
ギャップ計算を汚染しないため）。

**[実装決定・record 記録]** フレーズ内部（`has_join_to_prev=True`）のノートには
明示的な cursor シフトを加えていない。理由: `joins.assemble_v2` は run 内部を
`overlap_frames` のみで overlap-add 連結し、`NotePlacement.start_frame/end_frame`
は run 境界（run[0]/run[-1]）以外では未使用（コードパスを検証済み）。実データで
overlap < preutterance < vowel_core_start_frame が常に成立する（§2.1）ため、
overlap-add 接合そのものが「preutterance 相当の lead-in を暗黙に運ぶ」構造に
なっており、追加のシフトは不要と判断した。§5 Open Questions #3 に設計意図との
齟齬可能性を記録する。

### 1.8 consonants.py / 録音子音クリップの不使用（F1.4-B item3）

`donor="ritsu"` の VCV 経路では `consonants.apply_consonant_onset` も
`prepend_recorded_consonant` も呼ばない（子音は unit に録り込み済み）。
`render()` の結果辞書では `consonant_source="vcv"` を報告する（`vocadito`/`pjs`
は従来どおり synthetic/recorded/none を使用・無改変）。

**検証**: R3 の絶対グリッド化後も未解消であることを実測で確認した。`_build_vcv_placements`

### 2. `units.py:457`「Handle loop windows no longer than the overlap」（P2・`r3789428506`・採用）

**検証**: R5 で追加した `_loop_pad_raw_target` の overlap 損失補償
（`net_per_cycle = max(seg_len - overlap_frames, 1)`）は、`seg_len <=
overlap_frames`（短い unit を大きく伸長し、ループ中央区間がループ overlap
長 8 frame=40ms 以下になる場合）で破綻することを実測で確認した。この場合
`jn.overlap_add_concat` の内部クランプ（`ov = min(ov_req, prev_len,
cur_len)`）により `ov == cur_len` となり、`sp_p[ov:]` が空になって join
ごとの実際の正味増分は 0 フレームだった。旧式は `max(..., 1)` フォール
バックにより「常に最低 1 フレームは進む」と誤って仮定し、`n_cycles_needed`
を過小に見積もっていたため、`_ping_pong_pad_v2` が何ピース足しても出力長
が伸びず、R5 が排除したはずの凍結プラトー（`_force_length` の末尾フレーム
複製）が再発する条件が残っていた。

**修正**: `_effective_loop_overlap(seg_len, overlap_frames)`（新設）を
`_ping_pong_pad_v2`・`_loop_pad_raw_target` の両方から共通で呼び、
`_ping_pong_pad_v2` が `jn.overlap_add_concat` へ渡す overlap を
`min(overlap_frames, seg_len - 1)`（下限 0 = 非重畳連結へ縮退）へクランプ
するようにした（`sp_p[ov:]` に必ず最低 1 フレーム残ることを構造的に保証）。
`_loop_pad_raw_target` の生成量見積りも同じ実効値で `net_per_cycle` を
計算するよう揃えた上で、実測で判明した追加の乖離（base<->pad join の
接合損失は `_ping_pong_pad_v2` 内部のクランプ後の実効 overlap ではなく、
呼び出し側が渡す**素の** `overlap_frames` をそのまま消費するため、
`seg_len <= overlap_frames` では旧来の「+1 ピース」安全マージン
（`seg_len` フレーム分）がこの接合損失（`overlap_frames` フレーム）を
下回りうる——実測: `seg_len=6・overlap_frames=8` で凍結補填が 2 フレーム
残存）を埋めるため、`needed_extra = deficit + overlap_frames - seg_len`
を正味増分で満たす周回数を求める式へ変更した。

**音への影響確認（実測）**: 実データ（波音リツ強連続音 Ver1.5.1 + `--donor
ritsu --voicebank-root`）で sakura/umi の現行 VCV 選択（cache_fixed4、fixed4
WAV が使った選択結果と同一）を走査し、各ノートの `resolve_vcv_unit_to_note`
extended_looped 分岐で `center_hi - center_lo`（ループ中央区間長）と
`loop_overlap_frames`（既定 8 frame）の関係を実測した。

| score | 選択ノート数 | extended_looped 発動数 | `seg_len <= overlap_frames` 発動数 | 最小マージン（`seg_len - overlap_frames`） |
|---|---|---|---|---|
| sakura | 20 | 6 | **0** | +64 frame（note=16, unit=117） |
| umi | 12 | 3 | **0** | +66 frame（note=2, unit=118） |

sakura/umi のどちらの extended_looped 発動ケースも `seg_len` は 71〜98
frame（実測全件この帯）で、`loop_overlap_frames=8` から最小でも 64 frame
の余裕があり、本バグの発火条件（`seg_len <= 8`）には遠く届かない。
**したがって fixed4 WAV の bit には無影響であることを実測で確認し、fixed5
WAV の再生成は行わない**（バグ自体は実装上確実に存在し是正が必要だが、
現行の sakura/umi 選択が要求する unit 長は十分に長いため今回の対象範囲では
未発火だった）。

**テスト**: `test_ping_pong_pad_v2_progresses_when_seg_len_le_overlap`
（`seg_len=6 < overlap_frames=8` で `_loop_pad_raw_target` → `_ping_pong_
pad_v2` を直接呼び、出力長が `deficit` に対して十分伸びることを確認。旧
実装ではここで頭打ちしていた）+
`test_resolve_unit_to_note_no_frozen_plateau_when_seg_len_le_overlap`
（同条件を `resolve_unit_to_note` 経由の合成データで再現し、①凍結補填
（末尾の完全同一フレーム連続数）が高々 1 フレーム、②中盤区間が単調な
凍結値でなく実際に変化していることの両方を直接検証）の 2 本を追加。

**影響**: `seg_len > overlap_frames`（sakura/umi の現行選択を含む従来の
全ケース）では `_effective_loop_overlap` は `overlap_frames` をそのまま
