## 0. 裁定要約（本書で凍結する設計判断）

1. **学習の書き込み先は制御層から始める**（§1 候補 C）。重み学習（Adapter/LoRA）は
   制御層学習の天井が実測されるまで導入しない（backfill 原則）
2. **spk_embed の個体学習は恒久却下**（§1 候補 B）— 現行アーキテクチャでは
   Identity と技能が同一ベクトルに同居しており、学習 = 定義上 Identity drift になる
3. 自律性は **Level 1（稽古 = 人間が経験と recipe を選ぶ）から**。
   Level 2（自主練ループ）の解禁条件 = 耳と乖離しない校正済み自動評価軸 ≥ 1 本
   （run 4 評価器ギャップの実測より。評価器の深さが学習の深さの上限）
4. **TRANSFER_SKILL（差分移植 = 教育）を第 3 の Edge 種として語彙化**（§3）。
   同一モデル内の個体間でのみ成立。制御層版は Identity 非接触が構成保証、
   重み版（将来）は適用後の Drift Gate 必須
5. **文化島 + 移住ゲートは v0.3 素材として記帳のみ**（§4）— 現人口（一桁）では
   実装対象にしない
6. 当面の開発目標 = **VG-L0 最小実験**（§6）: run 5 checkpoint 上で制御層学習の
   1 遷移を回し「練習は未知曲に汎化するか」を測る

## 1. 学習の書き込み先（3 候補の裁定）

| 候補 | 内容 | 裁定 | 根拠 |
|---|---|---|---|
| A | 重み学習（Performance Adapter / LoRA 新設） | **保留** | 表現力最大だが GPU 学習・Replay Gate・drift 測定器（未校正）が全部必要。C の天井実測後に導入判断 |
| B | spk_embed の微調整 | **恒久却下** | 個体の個性が spk_embed 1 本に全部住んでいるため、学習 = Identity drift が構造的に不可分 |
| C | **制御層学習**（重み不変・制御パラメータのプロファイル） | **採用** | Identity 非接触が測定でなく**構成で保証**（声のモデルはバイト不変）。Replay 自明（決定論演奏）・遷移の記帳 = プロファイル diff・費用 ≈ $0 |

- 候補 C の「技能」の実体 = **個体別 versioned 制御プロファイル**（ブレス位置・
  アタック・フレーズ終端・音域別強弱など、合成入力を決定論的に加工する
  パラメータの束）。v0.2 §7.1 REPAIR_PERFORMANCE の「Adapter / control 限定」の
  control 側を主戦場にする読み
- C の天井（制御では届かない技能 — 発声そのもの・register transition の
  滑らかさ等）が実測されたとき、初めて A の導入根拠が立つ

## 2. 自律性レベル（どこまで学習させるか）

| Level | 内容 | 状態 |
|---|---|---|
| 0 | 学習なし（個体差 = 座標 + seed） | 現行 |
| 1 | **稽古（curated）**: 人間が経験データ・recipe を選び、遷移を実行し、耳ゲートで commit | **VG-L0 の対象** |
| 2 | **自主練（self-practice）**: 個体がテイク群を自動生成 → 自動評価 → プロファイル自動更新 | 解禁条件付き凍結: 耳と乖離しない校正済み自動評価軸 ≥ 1 本（VG-E1 の評価軸凍結と同一課題） |
| 3 | 本番中の自己更新（オンライン学習） | **恒久禁止**（v0.2 Determinism Contract 継承） |

- Level 2 を評価器で縛る根拠は実測: run 4 で LRA は「同等以上」・耳は「劣化」と
  割れた。この評価器で自主練を回せば個体は評価器ハッカーに育つ
  （v0.2 §9.1 の TrainGain/LearningGain 乖離の予防的適用）

## 3. TRANSFER_SKILL — 差分移植（教育）の語彙化

- 定義: 個体 A の学習差分 Δ_A（プロファイル diff / 将来は Adapter 差分）を、
  **B の Identity を変えずに B へ適用**する遷移。交配（Identity 混合）でも
  個体学習（自己の経験からの更新）でもない第 3 の Edge 種
- 成立条件: **同一モデル（同一 embedding 空間）内の個体間のみ**。
  別学習のモデル間では差分が意味を持たない（座標系が別）
- 安全性の非対称:
  - **制御層版**: Δ は記号的パラメータで A の声成分を含み得ない — Identity
    非接触が構成保証。無条件可
  - **重み版（将来）**: Δ_A は A の Identity を文脈に計算された勾配の産物で
    声色成分が絡み得る — 適用後の B' に Identity Drift Gate を必須とする
- 台帳: 来歴に「B の親 Revision + 移植元 = A の遷移記録」の両方を刻む
  （ラマルク型伝達を禁止でなく**監査可能**にする — v0.2 の Edge 分離原則の適用）
- **1:N 教育の決定論的分岐**: 同一教材（同一 Δ / 同一稽古）を N 個体に配っても、
  着地は「教材 × 個体の既在状態」の決定論的関数として個体毎に分かれる
  （乱数由来でない・全再現可能・差の原因が監査可能）。副産物 2 つ:
  1. **教材の評価**: 全個体で改善 → Identity 非依存に汎化する技能 /
     特定個体のみ → 声質条件付き技能、が集団実験で判別できる
  2. **可塑性の実測**: 同一教材への吸収度の個体差 = v0.2 H15（Plasticity
     Genome）の観測データが教育を回すだけで蓄積される

## 4. v0.3 素材（記帳のみ・実装しない）

- **文化島 + 移住ゲート**: 技能伝達（TRANSFER_SKILL）を島内に制限し、越境は
  外部操作の記帳付き移住イベントのみとする多様性維持機構（進化計算の島モデルの
  文化層適用）。遺伝の島と文化の島を**独立に**引ける（同一遺伝プールで別流派、等）。
  発動条件 = ④以降で Archive に人口が入ってから。スタイル収束
  （全個体が同一の最良 Δ に収束し演奏多様性が崩壊するモード）への対抗機構
- QD の守備範囲を Identity 空間から技能空間へ拡張する要否（上記収束モードの監視）
- 生物的制約の解禁一覧と各解禁が要求する会計（ラマルク伝達・死者との交配・
  N 親交配・反実仮想 A/B・不老と追い出し規則 — 議論記録として将来整理）

## 5. 禁止線（個体学習で変えないもの）

1. Identity 座標・spk_embed・共有 checkpoint は個体学習で不動
   （候補 C なら自動充足・A 導入時は freeze mask で強制）
2. 他個体の**声**からは学習しない — それは交配（進化 Edge）。学んでよいのは
   他個体の**制御プロファイル**まで（技能の模倣は可・声の模倣は不可）
3. 経験データは rights-clean のみ（v0.2 §8 の taint policy 継承）
4. commit は Training 評価器単独では不可 — 耳（ブラインド様式）または
   校正済み隠し軸を必ず経由

## 6. VG-L0 最小実験契約（当面の開発目標）

**問い: 制御層の「稽古」1 遷移は、未知曲に汎化する技能を作るか。**

| 要素 | 凍結内容 |
|---|---|
| 個体 | 固定 1 個体（run 5 checkpoint 上の既存話者 1 名。座標・seed 固定） |
| 課題曲 | 稽古曲 1 本（さくら/うみのどちらか）+ **未知曲 1 本**（汎化判定用・稽古に不使用） |
| 開放する制御軸 | 2–3 軸のみ（候補: ブレス位置オフセット・アタック強度・フレーズ終端処理。実装点 = 合成入力の決定論的前処理層。**現行 gate_synth の入力でどこまで表現できるかの実測が実装第 1 タスク**） |
| 稽古 | 制御軸の決定論的な水準組（グリッド）でテイク N 本を生成 → User ブラインド順位付け → 上位テイクの制御値を profile r1 として記帳（**選抜学習**: 勾配なし・決定の全過程が diff で読める） |
| 遷移記帳 | profile r0（既定値）→ r1 を、教材（テイク集合の pin）・判定記録・適用規則とともに台帳化（LearningTransition 記録の制御層版） |
| 判定 | 未知曲を r0 と r1 で合成し A/B ブラインド耳判定（run 4 で確立した同一区間 + 区間 LUFS 一致方式）。**r1 優位なら「稽古の汎化」成立** = v0.2 H10 の制御層版の初実測 |
| 費用 | GPU 学習ゼロ（推論のみ）。目安 < $1 |

Acceptance Criteria:

- [ ] 制御プロファイル schema v0（2–3 軸）と決定論的前処理層の実装 + テスト
- [ ] 稽古 1 遷移（r0→r1）の台帳記録（教材 pin・ブラインド判定記録・適用規則）
- [ ] 未知曲 A/B の耳判定記録（汎化の成立/不成立どちらでも dated record 化）
- [ ] 不成立の場合: 開放軸の選定が原因か制御層の天井かの切り分けメモ
  （候補 A 導入判断の入力）

## 7. トラック仮説（v0.2 H9–H15 に続く番号で登録）

- **H16（User 2026-08-19）**: 交配と学習の分離は品質と多様性のトレードオフを
  解消する — 交配層が多様性を（子は即戦力不要・品質圧に殺されず Identity
  空間を探索）、学習層が品質を（稽古は Identity 非接触・品質向上が多様性を
  削らない）それぞれ単独で担当できる。先行知見 = Baldwin 効果
  （学習による適応度地形の平滑化・Hinton & Nowlan 1987）と
  ミームティック・アルゴリズムの実測優位
- **検証予測**: ④第 0 世代を「素のまま」と「標準稽古 1 コース後」の両方で
  耳判定すると、稽古後の Quality Floor 通過率と Archive 充填率が上がる。
  **これは S2 の再解釈でもある** — 「誰でもない×破綻なし 0/10」は
  「生まれが悪い」と「無稽古」を区別しない判定だった。稽古後判定で
  通過が出れば、S2 の淘汰には育成可能個体が混ざっていたことになる
- **成立条件（会計）**: Archive 審査は**同一カリキュラム・同一稽古予算**の
  後で行う（稽古量の個体差が声質評価と交絡する「相続格差」の防止）
- **守備範囲外の明示**: 本仮説が守るのは Identity の多様性。歌い方
  （スタイル）の均質化は別問題で、対抗機構 = 文化島（§4・v0.3 素材）

## 8. 開発順序への組み込み

- 前提 = **run 5 checkpoint**（合成基盤）。GPU 学習を伴わないため
  **VG-E1（Probe 配線・評価軸凍結）と並行可能**
- 順序感: run 5 完了 → VG-E1 / VG-L0（並行）→ run 6（user 正規化+T3）→
  run 7（DX: Q7 分岐で つくよみ頂点 or あみたろ教師）
- VG-L0 の耳判定逐語は VG-E1 の評価軸語彙選定と Level 2 解禁判断の一次資料を兼ねる
