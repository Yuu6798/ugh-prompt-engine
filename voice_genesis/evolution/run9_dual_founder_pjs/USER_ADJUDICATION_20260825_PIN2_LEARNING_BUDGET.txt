【RUN9 User裁定 — PIN-2 前提】

1. config_sha の意味

config_sha は learning_recipe_sha と同一ファイルを指さない。

learning_recipe_sha:
PRACTICE_FROM_AUDIO / TRANSFER_TECHNIQUE の学習・探索手続きそのものを
凍結する正本。

config_sha:
RUN9 の実行時配線を確定する runtime orchestration config
`inputs/run9_execution_config.yaml` の raw byte sha256 とする。

execution config は各既存 pin / manifest / recipe を参照して束ねる。
trial_count、render_budget、stopping_rule 等の学習意味論を
config側で重複定義してはならない。


2. learning recipe 初期予算

PRACTICE_FROM_AUDIO:
  trial_count: 32
  render_budget: 128 logical_render_units per Founder

TRANSFER_TECHNIQUE:
  trial_count: 32
  render_budget: 128 logical_render_units per Founder

R9F-01 / R9F-02には各arm内で完全に同一の予算・候補生成規則・
探索空間・評価器・停止規則を適用する。

PRACTICEとEDUCATION間についても本RUN9では探索機会を揃えるため
同じtrial/render予算を採用する。
ただし入力情報境界の非対称性は実験変数として維持する。


3. stopping rule

FIXED_BUDGET_32_TRIALS_NO_SUCCESS_EARLY_STOP

gain成立・非成立を理由に途中終了しない。
32 trialsを原則最後まで消化する。

rights/provenance違反、immutable領域への書込企図、
非有限値、renderer/runtime failure、contract違反等の
Hard Failureのみ途中停止を許す。

NO_GAINは停止理由ではなく科学結果として記録する。


4. render_budget の単位

1 logical_render_unit =
1 Founderについて、凍結済み評価単位1件の音声renderを1回要求すること。

cache hitでも1 unitとして計上する。

128 unitsはlearning/search loop専用とし、
Birth baseline / C0 / C1 / validation / sealed holdout の
固定評価renderは別予算とする。

同一attempt内で結果を見てtrial_countまたはrender_budgetを追加してはならない。
不足と判断した場合は現attemptを凍結し、新design revisionで予算を再裁定する。
