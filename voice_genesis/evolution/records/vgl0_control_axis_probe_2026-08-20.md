## 2. 介入点の特定（合成パイプラインのどこで制御できるか）

`run_pipeline` は 3 段（linguistic → duration → pitch → acoustic → vocoder）。
DESIGN_VG_L0 §6 の候補 3 軸に対応する介入点は以下と判明した:

| 制御軸 | 介入点 | 性質 |
|---|---|---|
| **アタック強度** | duration 予測 `ph_dur_pred` の**後段**に係数を適用（子音音素のみスケール）。run_pipeline はこの予測比率をノート目標長へ rescale するため、**ノート長は不変のまま子音/母音の配分だけが動く** | **総尺不変** |
| **ブレス位置** | モジュール定数 `HEAD_FRAMES` / `TAIL_FRAMES`（前後の SP フレーム数） | 総尺が伸びる |
| **フレーズ終端処理** | `build_inputs` が返す `note_target_frames` の**最終要素**をスケール | 総尺が伸びる |

**重要な構造的発見**: アタック軸だけが「楽譜を変えずに歌い方を変える」性質を
持つ。ブレス軸と終端軸は**総尺を変える** = 楽譜（ノート配置）と干渉するため、
held-out 曲へ profile を適用する際は「同じ楽譜のまま歌い方だけ移す」という
VG-L0 の狙いから外れうる。制御プロファイル schema v0 では
**総尺不変軸と総尺可変軸を型で区別する**必要がある。

## 3. 実測結果

### 3.1 決定論（Render Reproducibility の前提）

同一条件 2 回（`baseline` / `baseline_repeat`）で **wav が sha256 完全一致**:
`787ca23d1de7a011…`。制御軸を通した合成経路は決定論を保つ。

### 3.2 可動性 — 3 軸すべて動く

| 条件 | wav sha256（先頭 12） | 総尺 (s) | RMS | 先頭 300ms RMS |
|---|---|---|---|---|
| baseline | `787ca23d1de7` | 8.5449 | 0.06950 | 0.15660 |
| baseline_repeat | `787ca23d1de7` | 8.5449 | 0.06950 | 0.15660 |
| attack ×0.25 | `e1897a872e09` | 8.5449 | 0.07922 | 0.14935 |
| attack ×0.5 | `9b4954f24066` | 8.5449 | 0.05764 | 0.12750 |
| attack ×1.5 | `e7d1208d8638` | 8.5449 | 0.09329 | 0.14633 |
| attack ×2.0 | `391f375bd729` | 8.5449 | 0.11609 | 0.02319 |
| attack ×3.0 | `8192c83fa20e` | 8.5449 | 0.10065 | 0.03299 |
| breath head40 | `20b6342f727a` | 8.9165 | 0.05450 | 0.00313 |
| breath tail40 | `0738256e2d7e` | 8.9165 | 0.10712 | 0.14097 |
| final ×1.5 | `64feb15a6788` | 8.9629 | 0.07491 | 0.12862 |
| attack ×2.0 + breath40 | `e31e0cf2c17b` | 8.9165 | 0.11884 | 0.00800 |

- アタック軸は**総尺 8.5449 s のまま**全水準で出力が変化（狙いどおり）
- ブレス head40 は先頭 300ms がほぼ無音（0.00313）= 息継ぎとして期待方向
- **直交性**: `attack×2.0 + breath40` は総尺がブレス側（8.9165）、RMS が
  アタック側（0.11884）、先頭 300ms がブレス側（0.00800）と、両軸の効果を
  同時に持つ。少なくともこの 2 軸は独立に組み合わせられる

### 3.3 中核の知見 — **制御パラメータは単調、音響応答は非単調**

介入後の子音フレーム比（duration 予測段での実測）:

| 条件 | 子音比（既定 → 適用後） |
|---|---|
| attack ×0.25 | 0.1923 → **0.0562** |
| attack ×0.5 | 0.1923 → **0.1064** |
| attack ×1.5 | 0.1923 → **0.2632** |
| attack ×2.0 | 0.1923 → **0.3226** |
| attack ×3.0 | 0.1923 → **0.4167** |

**制御量そのものは入力係数どおり単調**（0.056 → 0.417 まで滑らかに動く）。
一方 §3.2 の RMS は **非単調**（×0.25 の 0.079 が ×0.5 の 0.058 より高く、
×3.0 の 0.101 が ×2.0 の 0.116 より低い）。

この分離は VG-L0 の設計にとって決定的である:

- **グリッド設計は解析的にできる**（制御量は計算で予測でき、水準の等間隔性を
  保証できる）
- **しかし知覚品質の順序は予測できない**（モデルの非線形応答）。したがって
  「格子を細かく取れば品質も滑らかに動く」という前提は置けず、
  **稽古 = 選抜（耳による順位付け）という DESIGN_VG_L0 の方式は妥当**。
  勾配や補間で最適値を推定する方式は、この非単調性の上では成立しない
- 注意: RMS は粗い代理指標であり、非単調性が「知覚品質の非単調」なのか
  「RMS が指標として不適」なのかは本実測では**切り分けていない**。
  評価軸の選定は VG-E1 の軸凍結と合わせて行う（DESIGN_VG_L0 §8 の
  「耳判定逐語は VG-E1 の評価軸語彙選定の一次資料を兼ねる」）

## 4. 耳監査コストの見積もり（SB0 発動条件への入力）

2026-08-19 の裁定で、歌唱ベースライン設計文書（SB0）は棚上げ・**発動条件 =
「VG-L0 実測で耳監査が 1 遷移あたり 10〜12 ペアを超える」**とした。本実測から
の見積もり:

- 開放軸 3 本 × 水準 4（本実測の可動範囲から妥当）= **12 テイク/遷移**
- 総当たりペア比較なら 1 軸 4 水準 = 6 ペア × 3 軸 = **18 ペア → 発動条件を
  超える**
- ただし DESIGN_VG_L0 §6 が指定するのは「ブラインド**順位付け**」であり、
  N 本を並べて順序を付ける方式なら **3 セッション（軸ごと 1 回・各 4 本）**で
  済む。この方式なら発動条件に**達しない**

→ **SB0 の発動可否は「順位付けの実施形態」に依存する**。次段（稽古 1 遷移の
実施設計）で形態を確定させる時点が、SB0 再提出の判断点になる。本実測時点では
**発動を要求しない**（順位付け方式を採る前提）。

## 5. 次段への申し送り（制御プロファイル schema v0 の設計要件）

本実測から導かれる要件:

1. **総尺不変軸と総尺可変軸を型で区別する**（§2）。held-out 曲への転移では
   総尺不変軸を主軸に置く。総尺可変軸を含める場合、楽譜との干渉を
   profile 側で明示する
2. 制御量（子音比など）は**解析的に計算できる**ので、profile には
   「係数」ではなく**目標制御量**を持たせられる（曲やノート構成が変わっても
   同じ意味を保つ = 転移に必要な性質）
3. 決定論は確認済み（§3.1）。`learning-transition/0.1` の
   **Profile Transition Determinism** は構成で保証し、
   **Render Reproducibility** は既存の wav sha256 pin 規律をそのまま適用できる
4. 前処理層の実装形態は未定（本実測は monkeypatch）。gate_synth の
   read-only 契約を壊さない差し込み口（例: 制御プロファイルを引数で受け、
   既定 None なら現行と**バイト同一**の経路）を別 PR で設計する
