## 2. 介入点の特定（合成パイプラインのどこで制御できるか）

`run_pipeline` は **4 段**（linguistic → duration → pitch → acoustic →
vocoder。linguistic は duration 用と pitch 用に**2 回**呼ばれ、独立した
1 段ではない）。DESIGN_VG_L0 §6 の候補 3 軸に対応する介入点:

| 制御軸 | 介入点 | 本実測での総尺 |
|---|---|---|
| **アタック強度** | duration 予測 `ph_dur_pred` の後段に係数（子音音素のみスケール） | 不変（8.5449 s） |
| **ブレス位置** | モジュール定数 `HEAD_FRAMES` / `TAIL_FRAMES` | 伸びる |
| **フレーズ終端処理** | `build_inputs` の `note_target_frames` 最終要素をスケール | 伸びる |

**総尺不変は「軸の性質」ではなく実装位置の帰結**: run_pipeline は
`ph_dur_pred` を**ノート目標長へ per-note で rescale する**ため、その
**前**に介入すればノート長は保存される。ブレス/終端軸を長さ中立な形で
実装する（例: 総尺を保ったまま無音を内部で再配分する）ことは可能かも
しれないが、本実測では**試していない**。したがって「アタック軸のみ総尺
不変」と読むのは誤りで、正しくは「本実測の実装ではアタック軸のみ総尺
不変になった」。

**波及範囲の注意**: アタック軸の介入は duration 段の出力を変えるため、
下流の pitch 予測（`ph_dur` を入力に取る）にも波及する。「子音/母音の
配分だけが動く」は過小記述で、実際は**配分の変化を通じて pitch 曲線も
変わりうる**。

## 3. 実測結果

### 3.1 決定論

| 反復ペア | 制御軸 | 結果 |
|---|---|---|
| `baseline` / `baseline_repeat` | なし（既定値） | wav sha256 一致 `787ca23d1de7a011…` |
| `attack_x2.0` / `attack_x2.0_repeat` | **アタック軸 有効** | wav sha256 一致 `391f375bd729ba7b…` |

初版は baseline 反復のみで決定論を主張していたが、`consonant_scale == 1.0`
では patch が早期 return するため**制御軸の経路を一度も通っていなかった**
（セルフレビュー指摘）。制御軸を有効にした反復を追加し、そちらでも
sha256 一致を確認した。

### 3.2 可動性 — 3 軸すべて動く

**指標について**: gate_synth は wav を**ピーク 0.6 へ正規化**して書き出す
（`wav_peak` は全条件 0.6）。したがって wav から測った RMS
（`rms_norm`）は実質クレストファクタで、**単一サンプルの peak に支配される**。
一次指標には gate_synth 自身が record.json に残す**正規化前の生値**
（`wav_rms_raw` / `wav_peak_raw`）を使う。

| 条件 | wav sha256（先頭 12） | 総尺 (s) | **rms_raw** | peak_raw | rms_norm（参考） |
|---|---|---|---|---|---|
| baseline | `787ca23d1de7` | 8.5449 | 0.007329 | 0.063278 | 0.06950 |
| baseline_repeat | `787ca23d1de7` | 8.5449 | 0.007329 | 0.063278 | 0.06950 |
| attack ×0.25 | `e1897a872e09` | 8.5449 | 0.006921 | 0.052421 | 0.07922 |
| attack ×0.5 | `9b4954f24066` | 8.5449 | 0.007439 | 0.077433 | 0.05764 |
| attack ×1.5 | `e7d1208d8638` | 8.5449 | 0.006667 | 0.042876 | 0.09330 |
| attack ×2.0 | `391f375bd729` | 8.5449 | 0.006081 | 0.031430 | 0.11609 |
| attack ×3.0 | `8192c83fa20e` | 8.5449 | 0.006053 | 0.036085 | 0.10065 |
| breath head40 | `20b6342f727a` | 8.9165 | 0.007128 | 0.078481 | 0.05450 |
| breath tail40 | `0738256e2d7e` | 8.9165 | 0.007076 | 0.039631 | 0.10712 |
| final ×1.5 | `64feb15a6788` | 8.9629 | 0.007082 | 0.056718 | 0.07492 |
| attack ×2.0 + breath40 | `e31e0cf2c17b` | 8.9165 | 0.006101 | 0.030802 | 0.11884 |

全条件で wav sha256 が baseline と異なる = **3 軸とも出力に届いている**。

**組み合わせについて（直交性は主張しない）**: `attack×2.0 + breath40` は
総尺がブレス側、rms_raw がアタック側の値になる。ただし総尺は構成上必ず
ブレス側になるため独立性の証拠にならず、rms_raw の一致も 1 点観測に
すぎない。**両軸を同時に指定しても破綻せず、双方の効果が残る**ことまでが
言えることで、直交性の検証は行っていない。

### 3.3 制御量は単調 / 音響応答は**未判定**

介入後の子音フレーム比（duration 段での実測。制御量そのもの）:

| 条件 | 子音比（既定 → 適用後） |
|---|---|
| attack ×0.25 | 0.1923 → **0.0562** |
| attack ×0.5 | 0.1923 → **0.1064** |
| attack ×1.5 | 0.1923 → **0.2632** |
| attack ×2.0 | 0.1923 → **0.3226** |
| attack ×3.0 | 0.1923 → **0.4167** |

**制御量は入力係数どおり単調**（0.056 → 0.417）。ここは確定。

**音響応答の単調性は本実測では判定できない**:

- 一次指標 `rms_raw` は ×0.5 の 0.007439 を頂点に ×3.0 の 0.006053 まで
  下がるが、×0.25（0.006921）が ×0.5 より低く**反転が 1 箇所**残る。
  変動幅は 0.00605〜0.00744（約 ±10%）で、単調とも非単調とも断定できる
  精度がない
- 初版が中核に据えた「非単調」は**正規化後 RMS を見たことによる artifact**
  だった（反転 3 箇所は主に `peak_raw` の変動が作っていた）
- そもそも RMS（生値でも）は**知覚品質の代理として粗い**。「アタックが
  強くなったか」を測るなら音素境界の立ち上がりや子音区間のエネルギー比が
  要るが、本実測では測っていない

したがって「格子を細かく取れば知覚も滑らかに動くか」は**未判定**であり、
初版の「選抜（耳の順位付け）方式の妥当性が実測で裏づけられた」という主張は
**撤回する**。DESIGN_VG_L0 が選抜方式を採ること自体は設計判断として有効だが、
本実測はその根拠を与えていない。

### 3.4 可動範囲（破綻の有無）は未評価

`consonant_scale` は 0.25〜3.0、ブレスは 40 フレーム 1 水準（head/tail の
2 方向）、終端は ×1.5 の 1 点しか試していない。**どこまで動かすと音として
破綻するか**は聴取していないため未評価。次段のグリッド設計に必要な
「安全な水準幅」は本記録からは決められない。

## 4. 耳監査コストの見積もり — **算定不能（SB0 発動判断は次段へ）**

2026-08-19 の裁定で SB0 は棚上げ・**発動条件 = 「VG-L0 実測で耳監査が
1 遷移あたり 10〜12 ペアを超える」**とした。本記録での扱い:

- **本実測に耳判定は 0 件**であり、発動条件の述語（実測された耳監査量）を
  満たす材料が無い
- 初版は「3 軸 × 4 水準 = 12 テイク」を前提に 18 ペア vs 3 セッションを
  比較したが、(i) 水準 4 の根拠は §3.4 のとおり無く、(ii) DESIGN_VG_L0 §6 の
  「制御軸の決定論的な水準組（**グリッド**）」を軸独立スイープ（3×4=12）と
  読むか直積（4³=64）と読むかで桁が変わり、(iii) 発動条件の「ペア」を
  セッション単位へ読み替える操作も入っていた。**いずれも根拠のない
  読み替え**なので撤回する
- → **SB0 の発動可否は本記録では判定しない**。判定に必要なのは
  (a) グリッドの解釈確定、(b) 可動範囲の聴取評価に基づく水準数、
  (c) 順位付けの実施形態、の 3 点で、いずれも次段（稽古 1 遷移の実施設計）の
  成果物である

## 5. 次段への申し送り（制御プロファイル schema v0 の設計要件）

1. **総尺不変軸と総尺可変軸を型で区別する**。ただし §2 のとおりこれは
   実装位置の帰結なので、「ブレス/終端を長さ中立に実装できるか」を先に
   検討する余地がある
2. profile が持つ値を「係数」にするか「目標制御量（子音比など）」にするかは
   **未決**。目標制御量は曲やノート構成が変わっても意味を保つ利点があるが、
   実現には**曲ごとに duration 予測を走らせて逆算する**必要があり、
   「解析的に計算できる」わけではない（初版の記述を訂正）
3. 決定論は制御軸ありでも確認済み（§3.1）。ただし DESIGN_VG_L0 §6 は
   **Profile Transition Determinism（同一 r0 + 同一決定 → 同一 r1）と
   Render Reproducibility（同一 r1 → 同一 WAV）を分離し、前者の PASS を
   後者の PASS とみなすなと明記**している。本記録が確認したのは
   **後者だけ**であり、前者は profile schema と遷移規則の実装後にしか
   検証できない
4. 前処理層の実装形態は未定（本実測は monkeypatch）。gate_synth の
   read-only 契約を壊さない差し込み口（既定 None なら現行と**バイト同一**の
   経路）を別 PR で設計する
