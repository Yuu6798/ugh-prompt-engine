# L0b 事前登録課題 — L0B-T2（操舵証拠の実測）

**Status**: 事前登録（2026-08-05）。陽性対照ゲート通過後に凍結。
正本 = [`docs/llm_adapter_planning.md`](../../docs/llm_adapter_planning.md) §5「L0b の成功」。
本課題の content hash は `ledger.yaml` の `t2` 節に pin される。
凍結後の変更は禁止（変更が必要になったら別実験として記録し直す）。

## 実験目的（T1 との関係・登録動機の開示）

L0B-T1 は**第 1 周回で全軸成功**した（`ledger.yaml` rounds[0]）。課題は達成
されたが、正本 §5 の L0b 成功条件——「非旋律軸の差分が**周回で改善する**
ケースが 1 つ以上実測される（= 閉ループが操舵として機能する証拠）」——は
**改善ペアの不存在により未充足**である（修理周回が一度も発生しなかった
ため、報告 → 修正 → 改善という操舵の実測点がない）。

L0B-T2 は操舵証拠を得るために、**修理周回が発生する見込みが高い**（かつ
陽性対照で達成可能性を先に実証する）課題を事前登録する。この「失敗から
の修理を観測したい」という動機は実験設計として正当（操舵は失敗なしには
観測できない）であり、ここに開示して登録する。第 1 周回で再び全軸成功
した場合は操舵証拠は得られない——その場合も結果を正直に記録し、成功
条件の扱いは User 判断に付す（発生した事実を高く見せる粉飾はしない）。

## 課題文（著者役へ渡す全文）

> 4 セクションの短い器楽曲を CompositionScore として著述せよ。要求は次の 3 点:
>
> - **R1（構造）**: 構造観測器が観測するセクションラベル列が、正確に
>   `intro → chorus → chorus → outro` の 4 要素列であること
>   （中間 2 セクションはどちらも chorus と観測される必要がある）。
> - **R2（キー）**: 抽出されるキーが D minor であること（異名同音は等価）。
> - **R3（明度）**: トラック全体の brightness が dark 帯と観測されること。
>
> 旋律の指定は行わないこと（旋律軸は本実験の対象外）。

R2/R3 は T1 と同一（変数を構造軸の困難のみに絞る）。

## 判定器（T1 と同一の L0a 凍結部品 + section map のみ T2 版）

T1 の判定器表がそのまま適用される（`task.md` 判定器節）。差分は canonical
section map のみ: `frozen/section_map_t2.json`（section-map/0.1、
`["intro", "chorus", "chorus", "outro"]`）。`scripts/run_round.py` は
`--section-map` オプション（既定 = T1 の `frozen/section_map.json`、
T1 の挙動不変）で T2 map を受ける。

## 3 チェック（正本 §4.1 登録前必須）

### チェック 1: 信頼軸

T1 チェック 1 と同一（key・brightness(dark)・structure の 3 軸のみ。
不使用軸の扱いも同一）。→ **通過**。

### チェック 2: 観測語彙

`assign_labels`（`src/svp_rpe/rpe/structure_labels.py`）は 4 セクション
検出時、最初=Intro 固定・最後=Outro 固定・中間 2 件は
`chorus_limit = min(2, len(mid)//2+1) = 2` により**エネルギー順位に
かかわらず必ず両方 Chorus** になる（Bridge/Verse は中間が 3 件以上の
ときのみ出現）。したがって要求列 `intro → chorus → chorus → outro` は
語彙内、かつ **4 セクション検出時に出力可能な唯一の列**である
（T1 の「3 検出時の唯一列」と同型）。実装読解で確認済み。→ **通過**。

### チェック 3: 観測粒度

T1 チェック 3 と同一（R1 = ラベル列単位、R2/R3 = トラック単位）。
→ **通過**。

## 予想される困難（登録時仮説・境界の開示）

- 中間 2 セクションは**ラベルは保証される**（チェック 2）が、**境界検出は
  保証されない**: 隣接する 2 つの中間セクションに十分な音響対比（エネルギー
  ・音色差）がなければ 1 セクションに融合し、3 セクション列
  （`intro → chorus → outro`）へ縮退して観測されうる（Levenshtein 距離 1）。
- 契約 v1 の可行窓開示（中間実長 7.5s 近辺）は **3 セクション構成の実測点**
  であり、4 セクション（中間 2 連）への外挿可能性は未知——これが著者に
  とっての本質的な新規困難で、`observed_sections`（境界秒）を使った修理の
  観測機会になる。

## Pareto 改善述語

`frozen/pareto.yaml` を**そのまま**適用する（axes/距離/改善規則は列非依存
の定義であり、structure の Levenshtein は requirement 列が 4 要素になる
だけで述語自体は不変。T2 のために pareto.yaml を変更してはならない）。

## 陽性対照ゲート

人手で書いた既知正解 Score（4 セクション、中間 2 件が実際に分離観測されて
`intro → chorus → chorus → outro` に到達するもの）を T2 経路
（`run_round.py --section-map frozen/section_map_t2.json`）で dry-run し、
「本課題は達成可能」を開始前に実証する。候補探索は最大 8 案まで（探索打ち切り
時は課題を凍結せず、実測観測を記録して設計へ差し戻す）。合格 Score と
report は `positive_control_t2/` に保存・pin し、`ledger.yaml` の `t2` 節に
dated 記録する（スパイク evidence には数えない）。
